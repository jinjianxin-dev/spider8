# 11. PCA9685 转接方案：接线与固件切换

> 状态：固件已实现并编译通过；硬件在手（PCA9685 扩展板 + 8×MG90S），
> 等 5V/3A 适配器到货后按本文档接线。
>
> 定位：这是**舵机信号线的替代走法**，不是新需求。步态、动作、串口命令
> 与 08/09 文档完全一致，只有"PWM 从哪里发出来"变了。

## 1. 为什么 PCA9685 能顶上

PCA9685 是一颗 I²C 转 16 路 PWM 的芯片。ESP32 通过两根线（SDA/SCL）
告诉它"0 号通道输出 1500µs"，剩下的 50Hz 波形由它自己持续产生。

| 对比项 | LEDC 直连（原版） | PCA9685（本方案） |
|--------|------------------|-------------------|
| ESP32 占用引脚 | 8 根（GPIO4/5/6/7/15/16/17/18） | 2 根（GPIO8=SDA，GPIO9=SCL） |
| PWM 分辨率 | 14bit，1 份 ≈ 1.22µs | 12bit，1 计数 ≈ 4.88µs ≈ 0.44° |
| 标定精度 | 0.11°/µs 连续 | 每 0.44° 一档 |
| 供电风险 | 舵机线直接插 ESP32 排针（误插 5V 会烧板） | 舵机全在扩展板上，ESP32 上只有信号 |
| 接线量 | 8×3 根线到板子 | 8×3 根线到扩展板 + 4 根到 ESP32 |

精度差一点（0.44°/档）对 55mm 臂长的脚尖影响 ≈ 0.4mm，步态上无感。
trim 标定时会感觉到"每按一下跳一档"，这是正常现象。

## 2. 接线

```
5V/3A 适配器 ──┬── V+ 螺钉端子（红线，舵机电源）
               │
   1000µF 电容 ─┤ （长脚→V+，短脚→GND，注意极性）
               │
        GND ──┴── GND 螺钉端子 ──┬── 8 个舵机棕线
                                 └── ESP32 任意 GND 引脚（共地！）
PCA9685 VCC ← ESP32 3V3            （芯片逻辑电源，决定 I2C 电平）
PCA9685 SDA ← ESP32 GPIO8
PCA9685 SCL ← ESP32 GPIO9
```

舵机插扩展板排针，**通道号 = 固件 CH 号**，与 08/09 文档的关节表一致：

| 扩展板通道 | 关节 | | 扩展板通道 | 关节 |
|---|---|---|---|---|
| 0 | 左前·髋 | | 4 | 左后·髋 |
| 1 | 左前·膝 | | 5 | 左后·膝 |
| 2 | 右前·髋 | | 6 | 右后·髋 |
| 3 | 右前·膝 | | 7 | 右后·膝 |

**四条铁律（同 docs/09）：**

1. **V+ 与 VCC 是两个电源，不能混**：V+ 只接适配器 5V（舵机动力），
   VCC 只接 ESP32 的 3V3（芯片逻辑）。VCC 接 5V 会让 I2C 电平变 5V，
   ESP32 的引脚不耐 5V，会烧。
   > ⚠️ **本节是「基准接法」（VCC=3V3）**。实测若出现「波形全对、舵机就是不转」，
   > 根因是 3.3V 信号峰值不够，需要把 VCC 提到 5V —— **必须先按 §6.11 在
   > SDA/SCL 上加双向电平转换模块**，否则会烧 ESP32。不要只改 VCC 这一根线。
2. **三方共地**：适配器、PCA9685、ESP32 的 GND 必须连在一起，
   否则 I2C 通信直接失败，上电日志会打 `0x40 无应答`。
3. **OE 引脚必须接 GND**（低电平使能）。⚠️ 早期版本这里写成了"悬空即可、
   板上已拉高 = 输出使能"，是**错的**：PCA9685 的 OE 是 **active LOW**，
   拉高会**禁用全部 16 路输出**。部分板子 OE 带下拉电阻，悬空侥幸能工作；
   但不少国产板 OE 悬空会被拉成高电平，结果就是 I²C 通信、`status`、
   命令回显全部正常，**唯独 16 路输出全关、舵机一个都不动**，信号脚还会
   量到浮空的约 3.3V。**不要赌板子，直接用杜邦线把 OE 接到 GND。**
   地址跳线焊点全部不焊，地址就是默认 0x40。
4. **通道排针顺序看丝印，别只按舵机线颜色插**：不同厂家的 PCA9685 板，
   每个通道三根针的顺序可能是 `PWM / V+ / GND`，也可能是 `GND / V+ / PWM`。
   舵机线是 棕=GND / 红=V+ / 橙=信号。插反轻则不转，重则把 5V 灌进信号脚。
   上电前逐根对照板上的丝印确认。

## 4. 上电自检与验收

启动日志会多两行，看到它们才算后端活了：

```
pca9685: PCA9685 就绪：地址 0x40，SDA=GPIO8 SCL=GPIO9，50Hz / 12bit（1 计数≈4.88µs）
servo:   CH0 PCA0   髋 FL 关节  19.0° → 舵机  90.0° → 1500us
```

若打印 `PCA9685 0x40 无应答`，按顺序查：VCC 是否 3.3V → 共地是否接了 →
SDA/SCL 是否插反 → 地址跳线是否意外焊接。

验收步骤同 09 文档：先只插 0 号通道一只舵机 → `pwm 0 1500` 回中 →
`cal 0 24` / `cal 0 14` 点动核方向和幅度 → `save` → 逐通道推进。

`pwmscan` 的 LED 验证在 PCA9685 上同样可用（LED 接扩展板通道 +
GND 端子），只是万用表平均电压按 5V 折算（`pwm` 命令会自动换算）。

## 5. 已知差异 / 注意

- 12bit 精度：`cal`/`trim` 每步 0.44°，指令更细的步进会被量化到同一档。
- `pwmscan` 呼吸灯观感略"颗粒感"（每档 4.88µs），正常。
- I2C 总线加了互斥锁：步态任务与串口 raw 命令并发写不会撕裂波形。
- 单次 I2C 写失败只记警告、保持上一拍姿态（同 LEDC 后端的降级策略）。

## 6. 舵机标定（trim / dir）

装配舵机臂时，几乎不可能把 8 个臂都正好插在舵机的 90° 机械中点；而且左右脚的
舵机装法常常相反——同一个"前转 30°"命令，左前脚向前、右前脚却该向后。
固件用两个参数吸收这两类误差，标定一次后存进 NVS，断电不丢。
（本节与后端无关，LEDC 直连版同样适用。）

### 6.1 核心公式（servo.c 第 73 行）

```
舵机角 = 90° + (关节角 − 基准角) × dir + trim
```

- **90°**：舵机机械中点。装配时把舵机臂插在舵机自身标称 90° 的位置。
- **关节角**：上层算法想让该关节转到的角度（髋 0=竖直向下；膝 0=伸直）。
- **基准角**：站立时该关节应有的角度——髋 19°、膝 −38°（代码写死，8 路统一）。
- **dir**：方向镜像开关，取值 +1 / −1。左右脚装法相反时，给一侧设 −1。
- **trim**：装配误差微调，取值 −50° ~ +50°（`SERVO_TRIM_LIMIT_DEG`，
  2026-11-11 由 ±30° 放宽，原因见 `docs/13` §3）。舵机臂没插准时补偿用。

### 6.2 两个参数对照

| 你说的现象 | 参数 | 范围 | 命令 |
|-----------|------|------|------|
| 某只舵机要转到 60°/30° 才是站立位（臂没插准） | `trim` | −50°~+50° | `trim <0-7> <-50..50>` |
| 同命令左前脚前转、右前脚后转（左右镜像） | `dir` | 1 / −1 | `dir <0-7> <1\|-1>` |

### 6.3 这两个例子怎么设

**① "某只脚要转到 60° 才是站立"**
站立时关节角 = 基准角，公式里 `(关节角 − 基准角) = 0`，于是 舵机角 = 90° + trim。
要它停在 60°，则 **trim = −30°**。命令 `trim 0 -30`。
⚠️ trim 上限现为 **±50°**（早期 ±30°）。放宽是因为本机 360° 舵机把 `us_span`
从 2000 改成 1200 后，为保住站姿，旧 trim 要按 ×1.6667 换算，髋需要 −43° 左右。
若差得比 ±50° 还多，说明舵机臂物理装歪了，应把臂重插到 1500µs 站姿位置，
trim 只补"插完还剩的几度小误差"。

**② "左前脚前转 30°、右前脚却该后转 30°"**
这正是 dir 的活。左前/左后一般 dir=+1，右前/右后若发现转反了设成 −1：
`dir 2 -1`（2 = 右前髋）。哪几路要 −1 取决于舵机怎么装，需实测。

### 6.4 标定流程（接上舵机后做）

1. 上电，`status` 看默认：全部 dir=+1、trim=+0.0°。
2. 逐路点动验方向：`cal 0 40`（左前髋向前 40°）、`cal 2 40`（右前髋向前 40°），
   肉眼看腿往哪转。
3. 哪路转反了 → `dir <j> -1`。
4. 把狗摆成站立姿态，看每只舵机臂是否大致在 90°（装配基准位）；明显偏了就
   **先物理重插臂**，剩的小误差用 `trim` 补。
5. 8 路都满意 → `save`。

### 6.5 五个坑

- **`pose stand` 点了舵机不动是正常的。** 固件 `motion_init()` 上电就把 `s_out`
  填成站立角，`servo_init()` 也直接把 8 路摆到 90°；当前已经是站姿时再发
  `pose stand`，`motion_tick()` 算出的目标角与上一拍完全相同，`servo_apply()`
  写出的还是同一个 1500µs，舵机当然不会有任何可见动作。想让它动，必须发会
  **改变角度**的命令：`cal <j> <角度>`（点动）、`trim <j> <值>`（偏移）、
  `pose crouch/lie/shake/wave` 或 `walk`。标定台的「通电自检」按钮就是用 `cal`
  让选中通道在基准角 ↔ 基准角+25° 之间来回摆两次。
- **8 个舵机全都不动，先查 V+ 5V 有没有真的上电。** 烧写固件时按安全要求会
  先断开舵机电源，标定前容易忘记再打开。PCA9685 芯片自己由 VCC(3.3V) 供电，
  所以 V+ 没电时 I²C 照样应答、`status` 一切正常、`pose`/`cal` 也都有回显，
  唯独舵机没有电，极具迷惑性。同时确认三方共地、**OE 已接 GND**、舵机三根线
  （棕 GND / 红 V+ / 橙信号）没插反、没插到 8~15 号排针。
- **一招分清软件还是硬件**：敲 `cal 0 40` 再敲 `status`。若表里 CH0 舵机角
  变成 **111°**（90 + 40 − 19，基准髋角 19°），说明 I²C 已把脉宽成功写进
  PCA9685 寄存器，**软件链路全通**，问题在舵机供电或接线；若仍是 90°，才是
  固件/命令链路的问题。（注意 `cal` 命令自己回显的那个角度是直接按公式算的，
  而 `status` 表里的角度来自 `s_servo[]`——它只在 `servo_write_us()` 返回
  `ESP_OK` 时才更新，所以**只有 status 里的变化才算数**。）
- **但"status 变了"只证明芯片收到数据，不证明引脚真的在输出**：OE 被拉高时
  PCA9685 照样应答 I²C、照样写寄存器，输出却是全部关闭的。要验引脚，把 LED
  串 470Ω 接在 0 号通道**信号脚 ↔ GND** 之间，敲 `pwm 0 1500` 应微亮、
  `pwm 0 2500` 明显变亮（测完必须 `pwm off` 退出 raw 模式）。LED 不亮 →
  OE / VCC 问题；LED 会亮但舵机不动 → 舵机 5V 供电或线序问题。
  万用表直流档量信号脚，`pwm 0 1500` 时约 0.25V（输出高电平由 VCC=3.3V 决定，
  CLI 打印里按 5V 换算的 0.375V 偏大，量到 0.2~0.4V 都属正常）。
- `pwm` / `pwmscan` 是"裸脉宽"，**绕过 trim/dir**（servo.c 的 `servo_raw_us`
  注释写了不走 trim/dir/软限位）。它们只验证"这根线有没有波形"，**不能用来判方向**；
  判方向用 `cal`。另外 `pwm` 会进入 raw 模式冻结姿态，用完必须 `pwm off`。
- 改完 `dir`/`trim` **必须 `save`**，否则一断电重启又回到默认 +1 / 0，白调。

### 6.6 信号脚电压判读（万用表直流档，输出高电平 = VCC = 3.3V）

PWM 是快速跳动的方波，直流档量到的是**平均电压** = 3.3V × 脉宽 / 20000µs：

| 命令 | 占空比 | 正常读数 |
|---|---|---|
| `pwm 0 500` | 2.5% | ≈ 0.083V |
| `pwm 0 1500` | 7.5% | ≈ 0.248V |
| `pwm 0 2500` | 12.5% | ≈ 0.413V |

**判读**：

- **读数随脉宽明显变化**（0.08V → 0.41V）= 输出有 PWM，芯片正常，问题在舵机供电/线序。
- **恒定 ≈3.3V 且纹丝不动** = 输出被锁成恒高，或输出禁用后呈高阻（万用表高阻输入读到浮空电压）。四种可能：
  1. **OE 被拉高 / 悬空**（最常见）→ 直接把 OE 接 GND；
  2. **PWM 计数器没跑起来**（芯片仍在 SLEEP，或 `LEDn_ON == LEDn_OFF` 让输出锁死）；
  3. **量错脚**：I²C 的 SDA / SCL 空闲时也被上拉到 3.3V，读数同样"一直在 3.3V 左右"。**务必确认量的是 0 号通道排针的 PWM 脚**（通常是三根针里标 `PWM`/`S`/信号 的那根），不是 VCC、不是 SDA/SCL、也不是 V+；
  4. **固件把芯片配置错了**（AI / SLEEP / INVRT / PRESCALE）——本项目 2026-11-08 实际踩到，详见 §6.8。用 `pcadiag` 一眼看穿。
- **恒定 0V** = 输出恒低，多为 OE 禁用（MODE2.OUTNE=00 时 OE=1 输出低）或 VCC 没供电。

**最快的自检**：敲 `pwm 0 500` 量一次、`pwm 0 2500` 再量一次。两个数应该差约 0.33V；
若两次都是 3.3V，先接 OE→GND 再测，仍不行就用 `pcadiag`（见下）读芯片寄存器。
测完记得 `pwm off` 退出 raw 模式。

### 6.7 `pcadiag`：读回芯片寄存器（2026-11-08 新增）

固件新增串口命令 `pcadiag`（`pca9685.c` 的 `pca9685_diag()`），一次性打印
`MODE1 / MODE2 / PRESCALE / LED0_ON/OFF` 四组寄存器的**读回值**，用来定位
"I²C 写得进去、status 也正常，但输出脚恒 3.3V / 全 0" 这类故障：

| 读回项 | 正常值 | 异常含义 |
|---|---|---|
| `MODE1.SLEEP` | 0（MODE1=0x21） | =1 说明芯片没唤醒，PWM 计数器不跑 |
| `MODE1.AI` | 1（bit5 = 0x20） | =0 则 4 字节连写/连读全塌到同一寄存器，ON/OFF 会读成相同值 |
| `MODE2.INVRT` | 0（MODE2=0x04） | =1（MODE2=0x14）说明 PWM 极性反转，舵机收不到正脉冲 |
| `PRESCALE` | 121（≈50.03Hz） | 30 = 出厂默认 200Hz，说明 SLEEP 没进成、写入被忽略 |
| `MODE2.OUTDRV` | 1（推挽） | =0 是开漏，输出幅度可能不足 |
| `CH0 ON / OFF` | 0 / ≈307（1500µs 站姿） | OFF 没跟着命令变 = 脉宽没写进通道寄存器；ON==OFF = 输出锁成恒定电平 |

命令还会打印按 VCC=3.3V 换算的万用表预期读数，可与实测直接对照。

⚠️ **OE 是硬件引脚，寄存器读不到**。`pcadiag` 全绿但舵机仍不动时，
用万用表量 OE 对 GND 应 ≈0V；这一项只能靠接线解决。

同时加固了 `pca9685_init()`：每一步 I²C 写都检查返回值；RESTART 位在部分兼容
芯片上不自清，末尾再写一次 `MODE1=0x21` 兜底；初始化结束**逐项读回校验**
（SLEEP / AI / INVRT / OUTDRV / PRESCALE 任一不对直接返回错误，不再静默放行）。

### 6.8 实战复盘：信号脚恒 3.3V 的真正根因（2026-11-08，已修复）

把 OE 接 GND、共地、V+ 5V、线序全部排除后，信号脚依然恒 3.3V。烧入诊断固件后
敲 `pcadiag`，读回值如下，一眼看出问题不在硬件：

| 读回项 | 故障值 | 正常值 |
|---|---|---|
| `MODE1` | `0x00`（AI=0） | `0x21`（AI=1, SLEEP=0） |
| `MODE2` | `0x14`（INVRT=1） | `0x04`（INVRT=0, OUTDRV=1） |
| `PRESCALE` | `30` → 196.89Hz | `121` → 50.03Hz |
| `CH0 ON/OFF` | `257 / 257`（`pwm 0 2500` → `514 / 514`） | `0 / 307`（`pwm 0 2500` → `0 / 512`） |

**根因：`pca9685.c` 把两个位的含义张冠李戴了**（对照 NXP datasheet Rev.4 §7.3）：

| 位 | 旧代码误认为 | datasheet 实际 |
|---|---|---|
| MODE1 `0x20` | SLEEP | **AI（自动递增，bit5）** |
| MODE1 `0x10` | — | **SLEEP（bit4）** |
| MODE2 `0x10` | AI | **INVRT（输出反相，bit4）** |

连锁反应，逐条对得上现象：

1. `reg_write1(MODE1, 0x20)` 实际只开了 AI，**芯片从未进 SLEEP**；而 PRESCALE
   **只在 SLEEP=1 时可写**，所以写入 121 被无声忽略，芯片一直跑上电默认的
   `PRESCALE=30`（200Hz）。MG90S 只认 50Hz，自然不动。
2. `reg_write1(MODE2, 0x14)` 实际置了 **INVRT**，PWM 极性整个反过来。
3. 唤醒时又写 `MODE1 = 0x00`，**把 AI 清成 0**。于是 `pca9685_write_us()` 那次
   5 字节连写（`LED0_ON_L` 起 4 个数据字节）全部塌到同一个寄存器，
   最终 `ON == OFF`，输出锁成恒定电平 → 万用表读到恒 3.3V。
   `pcadiag` 连读 4 字节同样塌到同一寄存器，所以四个字节全是最后一次写的
   OFF 高字节（0x01 / 0x02），才出现 `ON=OFF=0x0101 / 0x0202` 这种诡异数字。

**为什么之前查不出来**：芯片靠 VCC 供电、I²C 一直正常应答，旧 init 又只校验
SLEEP 位、PRESCALE 不一致只打一条 warning 就返回 OK → `status`、`cal`、
命令回显全部漂亮，唯独输出不对。

**修复**：改用正确的位定义（`MODE1_AI=0x20` / `MODE1_SLEEP=0x10` /
`MODE2_INVRT=0x10` / `MODE2_OUTDRV=0x04`）；初始化序列改为
「MODE2=0x04 → MODE1=0x31(AI|SLEEP|ALLCALL) → PRESCALE=121 →
MODE1=0x21 唤醒 → MODE1=0xA1 RESTART → MODE1=0x21 兜底」，
全程保持 AI=1、INVRT=0；末尾读回五项校验，任一不符即失败。

**重新烧写后实测（已验证）**：

```
MODE1=0x21  AI=1  SLEEP=0  RESTART=0  ALLCALL=1
MODE2=0x04  INVRT=0  OUTDRV=1
PRESCALE=121 → 50.03Hz
CH0: ON=0 OFF=307 → 1499µs（站姿）
pwm 0 2500 → CH0: ON=0 OFF=512 → 2500µs
```

四项判读全 ✓。此时 0 号信号脚直流档应读 ≈0.247V（站姿）→ 0.412V（2500µs），
舵机可正常驱动，即可进入 §6 的 trim/dir 标定。

> ⚠️ 顺带记一个显示误差：`pwm` 命令的万用表提示曾按 5V 换算（2500µs 显示 0.625V），
> 而输出高电平实际由 **VCC=3.3V** 决定，真实值 ≈0.412V。
> 2026-11-08 已把 `console.c` 的 `pwm_print_one()` 统一改成 3.3V 换算（已编译，
> 下次烧写生效）；以 `pcadiag` 打印的 3.3V 换算值为准，纯显示差异不影响波形。

### 6.9 「信号脚 ≈0.2V 但舵机不动」——与 micro:bit 参考驱动逐项对照

#### 6.9.1 0.2V 是好消息，它精确等于中位脉宽

直流档读到的是方波**平均值**：`3.3V × 1500µs / 20000µs = 0.248V`。
实测 0.2V 左右 → 说明 OE 已使能、芯片跑在 50Hz、CH0 引脚确实在输出 PWM 方波，
且**峰值就是 3.3V**（若峰值是 5V，站姿应读到 0.375V）。

**头号陷阱：舵机在 1500µs 本来就不动。**
固件上电即站姿（8 路全 1500µs）。舵机臂如果本来就在中位附近，给它中位脉宽
就是"保持不动"——这与 §6.5 里"点『回到站姿』看不到动作"是同一个逻辑。
修复固件后若一直停在站姿、没发过改变脉宽的命令，看到的就是"电压正常但舵机不动"。

> **第一件事永远是点动**：`pwm 0 2500`（或 `cal 0 40` / 标定台「通电自检」），
> 电压应升到 ≈0.41V、舵机应转；测完 `pwm off`。

#### 6.9.2 与参考驱动（MakeCode / micro:bit TypeScript）对照

| 对照项 | 参考驱动 | 本项目 `pca9685.c` | 结论 |
|---|---|---|---|
| I²C 地址 / 振荡器 / 分辨率 | 0x40 / 25MHz / 4096 | 同 | 一致 |
| MODE1 位定义 | RESTART `0x80`、AI `0x20`、SLEEP `0x10` | 同（§6.8 修复后） | 一致 |
| MODE2 | OUTDRV `0x04` | `0x04`，并显式清 INVRT `0x10` | 一致，本项目更严 |
| 50Hz 预分频 | `round(25e6/(4096×50))−1 = 121` | 121，且读回校验 | 一致 |
| 通道写 | 5 字节 `[0x06+4ch, 0,0, off_l, off_h]`，ON=0 | 完全相同 | 一致 |
| µs→计数 | `round(us×4096/20000)` | `lroundf` 同式 | 一致 |
| 初始化顺序 | 读 MODE1→置 AI/清 SLEEP→MODE2→`setFrequency`(SLEEP→PRE→恢复→RESTART) | MODE2→`0x31`(AI\|SLEEP)→PRE→`0x21`→`0xA1`→`0x21` | 顺序不同，**终态相同**（pcadiag 实测 0x21/0x04/121） |
| MODE2 写法 | 读-改-写（保留旧位，**不会清掉误设的 INVRT**） | 直接写 `0x04`（清残留） | 本项目更稳 |
| RESTART 位 | 不清，靠芯片自清 | 显式再写一次 `0x21` 兜底 | 本项目更稳 |
| 读寄存器 | 每字节单独「写地址 + repeated start + 读」 | 依赖 MODE1.AI 连读 | 都可行，本项目已实测 |
| 边界保护 | `ticks≤0 → FULL_OFF`、`≥4096 → FULL_ON` | clamp 到 0~4095 | 500~3000µs 内无差别（3000µs ≈ 614 计数，远小于 4095） |
| **常高 / 常低输出** | **有 `setHigh`/`setLow`（FULL_ON/FULL_OFF）** | 无 | 参考多一个诊断手段 |
| 初始化自检 | 无 | 五项读回校验，任一不符即失败 | 本项目更严 |

**结论：没有任何一处差异会导致「寄存器全对、波形有、舵机不动」。**
在"把 1500µs 变成舵机轴上的转角"这件事上，两套驱动是等价的；`pcadiag` 的
四项实测值已经把这一点钉死。继续改固件不会有收益，问题在引脚之后。

#### 6.9.3 唯一实质电气差异：VCC 电平（3.3V vs 5V）

PCA9685 的 **PWM 输出高电平 = VCC**，与 V+ 端子的 5V 无关：

| | 本项目 | micro:bit 类方案常见接法 |
|---|---|---|
| VCC | ESP32 **3V3** | 常接 **5V** |
| PWM 信号峰值 | **3.3V** | **5V** |
| 站姿平均电压 | 0.248V（实测 0.2V ✓） | 0.375V |

部分 MG90S（尤其国产/杂牌）在 5V 供电下要求信号高电平 >3.5V，3.3V 落在
不确定区，会**完全不响应** —— 这是"波形正确但舵机不认"唯一说得通的电气原因。

> ⚠️ **安全红线：不能为了提幅值把 VCC 直接改接 5V。**
> PCA9685 的 SDA/SCL 由板上电阻上拉到 VCC；VCC=5V 会把 ESP32 的 GPIO8/9
> 拉到 5V，可能直接烧掉芯片，除非板子自带 I²C 电平转换。
> 先量 SDA 空闲电压确认上拉来源；确需提幅值请按 §6.11 在 **SDA/SCL 上加
> 双向电平转换模块后再把 VCC 改 5V**（推荐），或在 8 路输出上加缓冲提幅值，
> 或换用明确支持 3.3V 逻辑的舵机。

#### 6.9.4 点动后仍不动：三步定位

1. **量舵机插头端，不是量端子**：万用表量舵机**红线 ↔ 棕线**是否有稳定 5V。
   端子上有 5V 不代表舵机那头有（排针 V+ 与端子 V+ 在部分板上靠跳线连通）。
2. **确认电压随脉宽变**：`pwm 0 500` ≈0.08V → `pwm 0 2500` ≈0.41V。
   跟着变 = 芯片到引脚全通；不跟着变 = 回到 §6.7 用 `pcadiag`。
3. **逐根看排针丝印**：各家通道三针顺序不同（`PWM/V+/GND` 或 `GND/V+/PWM`），
   别按舵机线颜色盲插。确认橙线落在标 `PWM`/`S` 的针上、红线那根对 GND 是 5V。

三步全过、舵机仍不动 → 按 §6.9.3 处理信号幅值（加电平转换），或换一只舵机
排除个体损坏。

### 6.10 实测「0.2V → 0.40V，舵机仍不动」：证据链收口与三点测量

#### 6.10.1 这组读数说明软件链路已经全部证实

| 命令 | 实测 | 理论（VCC=3.3V） | 判定 |
|---|---|---|---|
| 站姿 `1500µs` | ≈0.2V | 0.248V | ✓ |
| `pwm 0 2500` | ≈0.40V | 0.413V | ✓ |

**「电压一直在 0.40、没有波动」是正确的、不是故障**：万用表直流档显示的是
50Hz 方波的**平均值**，方波远快于万用表采样率，读数本来就该稳定不跳；
要看跳动需切交流档 / 频率档或用示波器。真正该看的"波动"是**换命令后的读数变化**，
而 0.2V → 0.40V 已经发生了，说明：

1. 命令解析生效（进入 raw 模式并写入 2500µs）；
2. I²C 写寄存器成功、AI 递增正常、极性/频率正确；
3. OE 已使能、PWM 计数器在跑、通道引脚真的在输出方波。

反推峰值：`0.40V × 20000µs / 2500µs = 3.2V ≈ 3.3V`，与 VCC=3V3 完全吻合
（若峰值是 5V，站姿就该读到 0.375V 而不是 0.2V）。

> **结论：ESP32 → I²C → PCA9685 → 通道排针 这一段已 100% 排除。**
> 再改固件、再烧写、再调 `pcadiag` 都不会有收益。剩下的只可能是
> **排针 → 舵机插头 → 舵机本体** 这一段，或 **3.3V 信号幅值**不被这只舵机接受。

#### 6.10.2 三点测量（一锤定音）

黑表笔**始终点在舵机的棕线（GND）上**，不要点 PCA9685 板的 GND —— 只有以舵机
自己的地为参考，量到的才是舵机真正"看到"的电压。共地缺失时用板子 GND 量会
"看起来全对"，极具迷惑性。

| # | 红表笔 / 档位 | 正常值 | 不达标说明 |
|---|---|---|---|
| ① | 舵机**红线**（V+），直流电压档 | 稳定 **5V**（≥4.8V） | 舵机没电：V+ 电源没开 / 端子到排针 V+ 不通 / 三线插反 |
| ② | 舵机**橙线**（信号），直流电压档 | 2500µs 时 **≈0.40V** | 信号没送到舵机：橙线插错针 / 排针丝印顺序不同 / 插头接触不良 / 插到 8~15 号通道 |
| ③ | 舵机**棕线 ↔ PCA9685 GND**，通断/电阻档 | ≈0Ω、蜂鸣导通 | 没共地：信号没有参考电平，舵机收不到脉冲 |

**判读**：

- 任一不达标 → 按对应行处理（供电 / 共地 / 线序），这是接线问题，不用碰程序。
- **三点全过仍不动** → 只剩两种可能：
  1. **信号峰值 3.3V 不够**（§6.9.3）：按 §6.11 提幅值，或换一只明确支持
     3.3V 逻辑的舵机。**禁止把 VCC 直接改接 5V**。
  2. **舵机个体损坏**：换一只同型号，或用 5V + 已知 PWM 源单独点一下。

> **2026-11-09 实测结论**：用户三点测量全过，且同一只舵机在 micro:bit +
> MakeCode PCA9685 驱动下能正常转动 → 第 2 条（舵机损坏）也已排除。
> **根因锁定为第 1 条：3.3V 信号幅值。** 详见 §6.11。

#### 6.10.3 两条操作提醒

- `pwm` 会进入 raw 模式冻结步态，测完必须 `pwm off` 回到站姿。
- `2500µs` 是舵机极限角度，**不要长时间保持**，否则舵机顶在限位上持续堵转发热。

工具侧：`tools/servo_calib.html` ② 之后新增「🔎 三点测量」向导，三个下拉选完
点「给出结论」会按上述判据自动给出对应处理建议（不需要串口，随时可用）。

#### 6.11.1 当时的证据链（后被证伪）

用户回报：三点测量 **①②③ 全过**，且**同一只舵机在 micro:bit + MakeCode
PCA9685 驱动下能正常转动**。至此全部排除：

| 已排除 | 依据 |
|---|---|
| 舵机供电 / 线序 / 插头接触 / 共地 | ① 5V、② 0.40V、③ ≈0Ω，且都在**舵机插头端**量的 |
| 舵机本体损坏 | 同一只舵机在 micro:bit 上会动 |
| 固件 / 寄存器 / 频率 / 极性 / OE / 通道映射 | §6.10.1 的 0.2V→0.40V + `pcadiag` 四项读回 |
| 脉宽映射与 MakeCode 驱动不一致 | §6.9.2 逐项对照等价 |

两边唯一剩下的差别是 **PWM 高电平幅度**（PCA9685 输出峰值 = VCC）：

| | 本项目（基准接法） | micro:bit 那套 |
|---|---|---|
| PCA9685 VCC | ESP32 **3V3** | 板上 **5V** |
| 信号峰值 | **3.3V** | **5V** |
| 站姿 1500µs 平均电压 | **0.248V**（实测 0.2V） | 0.375V |

MG90S 在 5V 供电时，输入高电平门槛典型 **≥0.7×Vdd ≈ 3.5V**。3.3V 落在
门槛之下，舵机内部比较器把整条脉冲判成"一直是低电平"，于是**完全不响应**——
脉冲宽度再标准、频率再准也没用。就像有人隔着门用刚好听不见的音量喊口令，
口令内容完全正确，屋里的人就是不动。

> **这不是软件问题，不用再改固件、重烧或调 `pcadiag`。** 需要改的是电气接线。

#### 6.11.2 30 秒交叉验证（可选，不用改线）

在 micro:bit 那套**能正常转动**的接法上，万用表直流档量舵机**橙线 ↔ 棕线**，
站姿中位（1500µs）时：

- 读 **≈0.375V** → 峰值 5V，根因确认；
- 读 **≈0.248V** → 峰值也是 3.3V，说明幅值不是原因，需回头查通道写入/频率（概率很低）。

公式：`平均电压 = 信号峰值 × 脉宽 ÷ 20000µs`。

#### 6.11.3 方案 A（推荐）：I²C 侧加双向电平转换，VCC 提到 5V

**只需 2 路转换**（SDA、SCL），比在 8 路输出上逐个抬电平省事得多，且
PCA9685 的 8 路输出天然变成 5V 幅度。买一块 **2 路 / 4 路 BSS138 双向
电平转换模块**（也叫 "Logic Level Converter"、"I²C 电平转换模块"）即可。

```
ESP32-S3                    双向电平转换模块              PCA9685
─────────                  ────────────────              ───────
3V3      ──────────────→  LV  (低压侧电源)
GPIO8 SDA ─────────────→  LV1  ── HV1 ──────────────→  SDA
GPIO9 SCL ─────────────→  LV2  ── HV2 ──────────────→  SCL
GND      ──────────────→  GND  ←── 适配器 5V ──────→  HV (高压侧电源)
                                        5V ─────────→  VCC  ← 改这里！
                                        5V ─────────→  V+   (舵机电源)
                                        GND ─────────→  GND / OE
```

改动清单：

1. **拔掉**原「ESP32 3V3 → PCA9685 VCC」这根线；
2. PCA9685 **VCC 改接适配器 5V**（与 V+ 同源），**V+ 保持 5V**；
3. SDA / SCL **不再直连 ESP32**，改为经电平转换模块的 LV↔HV 两侧过渡；
4. 模块 LV 侧电源接 ESP32 3V3、HV 侧电源接 5V，**模块 GND 与三方共地**；
5. OE 仍接 GND；地址跳线仍不焊（0x40）。

要点与风险：

- ESP32 的 GPIO8/9 只接触 LV 侧（3.3V），**安全**；5V 只出现在模块 HV 侧之后。
- 板载 SDA/SCL 上拉电阻与模块 HV 侧上拉并联（约 10k∥10k=5k），
  5V/5k = 1mA，在 I²C 规范（≤3mA）内，100k/400kHz 都稳定。
- 若板子有「VCC ↔ V+ 短接跳线」，确认它不会把 5V 倒灌到 ESP32 3V3。
- **固件一行都不用改、不用重烧**：I²C 地址、50Hz、脉宽计算、8 路通道全不变。
- 唯一影响：`pwm` / `pcadiag` 打印的万用表预期电压仍按 3.3V 换算，改完会
  显示偏低；实测按 `5V × 脉宽 ÷ 20000µs` 心算对照即可。

#### 6.11.4 方案 B（备选）：保持 VCC=3V3，只抬 8 路输出

不动 I²C，在 PCA9685 的 8 个 PWM 脚与舵机橙线之间加一级 5V 供电的缓冲：

- **74AHCT125 × 2**（4 路三态缓冲，共 8 路）或 **74AHCT245 / 74HCT244 × 1**（8 路）；
- 缓冲芯片 VCC 接 5V、GND 共地、使能脚（/OE）接 GND；输入接 PCA PWM，输出接舵机橙线；
- AHCT 系列在 5V 供电时 **VIH(min)≈2.0V**，能可靠识别 3.3V 输入，输出即 5V 幅度；
- BSS138 开漏上拉模块也能凑合，但上升沿靠上拉电阻，边沿不如推挽干净（50Hz 够用）。

缺点：要处理 8 根线、多一片芯片；优点：I²C 完全不用动，接线风险最低。

#### 6.11.5 绝对禁止

> **不能只把 PCA9685 的 VCC 从 3V3 改到 5V、SDA/SCL 仍直连 ESP32。**
> 板上 SDA/SCL 上拉到 VCC，会把 ESP32-S3 的 GPIO8/9 抬到 5V，
> 超过 GPIO 绝对最大额定 3.6V，可能直接烧掉芯片。

#### 6.11.6 改完怎么验收

| 步骤 | 期望结果 |
|---|---|
| 上电 → `pcadiag` | `MODE1=0x21 / MODE2=0x04 / PRESCALE=121 / ON=0 OFF≈307`，与改线前一致 |
| `pwm 0 1500` → 量橙线↔棕线 | **≈0.375V**（原 0.248V），舵机应归中 |
| `pwm 0 2500` → 量橙线↔棕线 | **≈0.625V**（原 0.413V），舵机应转到极限角 |
| 逐通道 `pwm <0-7> 1500` | 8 个舵机都应有反应 |
| 测完 | `pwm off` 回站姿；2500µs 不要长时间保持（顶限位堵转发热） |

### 6.12 5V 也不动之后：控制变量，别再猜（2026-11-09 18:08 更新）

#### 6.12.1 软件链路彻底结案

逐行核对用户提供的 micro:bit MakeCode 驱动与本固件 `pca9685.c`：

| 环节 | MakeCode 参考驱动 | 本项目 | 判定 |
|---|---|---|---|
| `init()` MODE1 | 读回→置 AI(0x20)→清 SLEEP | `0x31`(AI+SLEEP+ALLCALL) → `0x21` | 等价 |
| `init()` MODE2 | 读回→置 OUTDRV(0x04) | 写 `0x04`（INVRT=0） | 等价 |
| 50Hz | `round(25e6/(4096×50)−1)=121` | 写 121，读回 121 | 等价 |
| 进 SLEEP 写 prescale | `(oldMode&0x7F)|0x10` → 写 0xFE → 恢复 | 同一顺序 | 等价 |
| 唤醒 / RESTART | 恢复 oldMode → `|0x80` | `0x21` → `0xA1` → `0x21` | 等价（多一次清 RESTART，读回 0x21 已自清） |
| 通道写入 | `[0x06+4ch, on_l, on_h, off_l, off_h]` | 同，`ON=0` | 等价 |
| 脉宽换算 | `round(us×4096/20000)` | `lroundf(us×4096/20000)` | 等价 |
| `setPulse` 边界 | 0→fullOff、≥4096→fullOn | clamp 到 4095 | 边界略有别，1500µs 无关 |

**结论：不再改固件、不再重烧、不再调 `pcadiag`。** `pcadiag` 读回 +
0.2V→0.40V 已证明寄存器、频率、极性、OE、通道输出全对。

#### 6.12.2 剩下的都是「万用表量不出来」的东西

| # | 嫌疑 | 为什么三点测量没发现它 |
|---|---|---|
| 1 | **供电带载不足**：舵机启动瞬间拉 0.5~1A，5V 塌到 3~4V，舵机内部 MCU 反复复位 | ① 是**空载/静态**量的 5V，舵机没转时电流很小，读数永远漂亮 |
| 2 | **对照实验不是控制变量**：micro:bit 那套可能是另一块扩展板、另一个电源、另一组杜邦线 | "在 micro:bit 上会动"只证明舵机本体好，不证明这边的电源/接线好 |
| 3 | **信号没真正到舵机**：量的是板上 CH0 排针，舵机却插在别的通道 / 插头接触电阻 | 排针上有 0.40V ≠ 舵机芯片引脚上有 0.40V |
| 4 | 波形边沿/毛刺 | 万用表直流档只看平均值，看不出上升沿 |

#### 6.12.3 三个决定性实验（按性价比排序）

**A. 只换控制器（最干净，不需买东西，前提是 micro:bit 用的是同一块 PCA9685）**
保持 PCA9685 板、5V 电源、舵机、所有杜邦线**完全不动**，只把 SDA/SCL 两根线
从 micro:bit 改接到 ESP32 GPIO8/9，并把 ESP32 GND 接进共地。
- 还是不动 → 变量锁定在 ESP32 侧/固件（此时才回头查软件）；
- 动了 → 原来的电源或接线有问题，与固件无关。

**B. 绕开 PCA9685（次选）**
把 `sdkconfig` 切回 `CONFIG_SERVO_BACKEND_LEDC`，重烧后 GPIO4 直接接舵机橙线
（3.3V 信号、50Hz、1500µs，完全不经过 I²C 和 PCA9685）。
- 动了 → 问题在 PCA9685 板/接线/电源那一侧；
- 还不动 → 与固件彻底无关，只可能是电源、共地或舵机接线。

**C. 10 秒快验（做 A/B 之前先做）**
万用表黑笔点舵机棕线、红笔点舵机**红线**，保持不动；发 `pwm 0 2500` 的瞬间
盯读数：若从 5V 掉到 4V 以下 → 第 1 条坐实，换独立 5V/2A 以上电源、
只插一只舵机再试。同时把 8 只舵机减到 1 只，排除总电流不足。

#### 6.12.4 已确认的三个事实（18:08 用户回报）与电池盒线索

| 问题 | 用户回答 | 判读 |
|---|---|---|
| 5V 改在哪 | **PCA9685 的 VCC** | 信号峰值能抬到 5V，但 SDA/SCL 直连 ESP32 时上拉也变成 5V，I²C 可能已不稳定 → **这次「5V 也不行」的实验结果本身不完全可信** |
| 改后站姿读数 | **没量** | 无法确认 5V 是否真生效（板载 LDO / 电池电压 / 接错脚都可能让它仍是 3.3V） |
| 舵机 5V 来源 | **电池盒** | ⚠️ 当前第一嫌疑，见下 |

**电池盒是本次最强线索。** 4×AA 电池盒内阻大、放电能力弱：

- 空载/静态时万用表量到 5V 很正常，但舵机启动瞬间要 0.5~1A，电压会塌到 3~4V；
- 本项目同时插 **8 只** MG90S，静态电流就不小，一齐上电更容易把电池盒拉垮；
- 舵机内部 MCU 欠压复位 → 表现为「完全不动」，而寄存器、频率、极性、信号波形全都是对的；
- micro:bit 那套大概率只接 1 只舵机、或用了别的电源 → 对照不满足控制变量。

碱性新电池 4 节是 6V（MG90S 上限 6V，已到边），镍氢 4 节只有 4.8V，旧电池更差 ——
无论哪种，带载能力都比 5V/2A 适配器差一个数量级。

#### 6.12.5 下一步：三步验电（约 10 分钟，不用买东西）

0. **先把 VCC 改回 3V3**：VCC=5V 且 SDA/SCL 直连 ESP32 会把 GPIO8/9 抬到 5V
   （超过 3.6V 绝对最大额定）。恢复基准接法，否则后面所有测试都不可信。
1. **拔掉 7 只舵机，只留 CH0 这一只**，排除总电流不足。
2. **带载量电压**：黑笔舵机棕线、红笔舵机红线，眼睛盯住读数，然后发
   `pwmscan 0`（500→2500µs 扫两轮）或 `pwm 0 500` / `pwm 0 2500` 来回切。

   | 现象 | 结论 / 下一步 |
   |---|---|
   | 读数始终 ≥4.8V | 供电过关 → 走 §6.12.3 实验 A（只换控制器） |
   | 掉到 4V 以下 / 明显跳变 | **供电带载不足坐实** → 换全新电池或 5V/2A 以上适配器、充电宝，再重试 |
   | 舵机抖一下又停 | 典型欠压复位，同上 |

   顺手量一下电池盒空载电压：碱性 4 节应 ≈6V、镍氢 ≈4.8V，低于 4.8V 先换电池。
3. 供电过关仍不动 → 做 §6.12.3 的 **实验 A**（保持板/电源/舵机不动，只把 SDA/SCL
   从 micro:bit 换到 ESP32 GPIO8/9）或 **实验 B**（切 LEDC 后端，GPIO4 直连舵机橙线）。

> 补量一个读数：若改 5V 那次还能复现，站姿橙线↔棕线应读到 ≈0.375V；
> 仍是 ≈0.2V 就说明 VCC 根本没到 5V，那次实验无效。

> 安全提醒仍然成立：**PCA9685 的 VCC 直接接 5V、SDA/SCL 直连 ESP32 是禁止的**
> （板上上拉会把 GPIO8/9 抬到 5V，超过 ESP32-S3 绝对最大额定 3.6V）。
> 若已经这样接过，先恢复 VCC=3V3 再继续排查。
