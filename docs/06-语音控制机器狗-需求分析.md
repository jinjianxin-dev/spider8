## 1. 项目概述

在两块已有成果的基础上，给机器人装上"耳朵"和"理解力"：

1. **spider8 蜘蛛机器人**：4 条腿 × 每腿 2 关节 = 8 个舵机——这个硬件布局与典型四足机器狗完全一致。更换结构件（腿件/外壳）后即改造为**四足机器狗**，主板、舵机驱动、FreeRTOS 框架全部复用。
2. **esp32-gpio-llm**：已在 ESP32-S3 上离线运行的 31 万参数中文指令理解模型（`cmd-zh-s0.pt`），不联网、不依赖手机。把它的"理解指令"能力从**控制 GPIO 引脚**迁移到**控制机器狗动作**。

最终目标：**对着狗说一声"小八小八"，再说"往前走""坐下""握手"，狗就照做——全程离线。**

### 1.1 一句话比喻

- **唤醒词**（"小八小八"）＝ 敲门：敲了门，狗才竖起耳朵听你说什么。
- **命令词**（"前进""坐下"）＝ 点菜单：说得标准就秒懂，快且不会理解错。
- **LLM 模型** ＝ 翻译官：你随口说"走快点""往前挪挪"，菜单上没有的句子，由它翻译成标准动作。
- **硬件校验层** ＝ 门卫：不管前面谁批准的，超出安全范围（速度太快、时间太长）一律拦下。

### 1.2 来自 gpio-llm 训练的三条铁律（本项目全程遵守）

| 铁律 | 原话依据 | 在本项目中的落地 |
|---|---|---|
| 解析器优先，模型只兜底 | 手写解析器"做错事 0.0%"，模型 10.8% | 命令词层（ESP-MultiNet）先行，LLM 只处理命令词覆盖不了的说法 |
| 模型永远会抢答，安全靠架构 | "switch off pin 100" 曾被悄悄解析成 pin 10 | 模型可输出"不存在的动作名"，由硬件层**按名字拒绝**，而非换成最近的动作 |
| 语料决定能力边界 | "60 秒→6000"的丢零 bug、"闪烁类 31%" 均为语料覆盖缺口 | 为机器狗动作域重建语料，补齐中文语序模板（副词前置等），另写全新保留集 |

## 2. 硬件需求（新增部分）

在《01-需求分析》H1~H8 基础上新增：

| 序号 | 部件 | 方案 | 说明 |
|---|---|---|---|
| H9 | 麦克风 | INMP441（I2S 全向 MEMS 麦克风） | 3.3V 供电，I2S 数字输出，抗模拟噪声；约 5~10 元 |
| H10 | 扬声器（可选，P1） | MAX98357A（I2S 功放）+ 3W 小喇叭 | 语音反馈"好的/已停止"；预算紧可先用蜂鸣器音效代替 |
| H11 | 结构件 | 四足机器狗腿件/外壳（3D 打印或改装套件） | 替换蜘蛛腿件，舵机位与现有 8 舵机布局对齐 |
| H12 | 麦克风支架 | 麦克风开孔朝前、远离舵机 | 舵机堵转噪声是离线语音的大敌（见风险 R4） |

**不新增主控**：ESP32-S3-N16R8 是乐鑫官方 AI 语音方案的标准载体（ESP-SR 全家桶专为 S3 的向量指令优化），16MB Flash + 8MB PSRAM 余量充足（预算见设计文档 §5）。

## 3. 功能需求

> 编号规则：FR-V* = 语音新增功能需求，与《01-需求分析》FR-1~FR-6（遥控/爬行/避障等）并列。

### FR-V1 语音唤醒（P0 必做）

- 说唤醒词（初定"小八小八"，备选乐鑫免费唤醒词）后进入命令聆听状态
- 非唤醒状态下持续拾音但不解析，误唤醒目标：安静环境 ≤ 1 次/天，1 米内正常音量唤醒成功率 ≥ 95%
- 唤醒后有即时反馈（蜂鸣一声/眼睛亮起），8 秒内无有效命令自动回到待唤醒状态

### FR-V2 命令词直接控制（P0 必做，主通道）

固定命令词表（初版 30~60 条，走确定性识别，快且稳）：

| 类别 | 命令词示例 | 对应动作 |
|---|---|---|
| 行走 | 前进 / 后退 / 左转 / 右转 / 停 / 停止 | 步态引擎方向指令 |
| 速度 | 快一点 / 慢一点 / 慢速 / 快速 | 调步态速度档 |
| 距离/时长 | 走三秒 / 向前走五步 | 限时/限步行走 |
| 姿态 | 坐下 / 趴下 / 站起来 / 起立 | 静态姿态 |
| 卖萌 | 握手 / 打个招呼 / 跳个舞 | 组合动作（依赖原 M5 动作库） |
| 查询 | 电量多少 | 播报电量（或蜂鸣音效档位） |
| 急停 | 停！/ 停下（任意时刻可打断） | 立即冻结所有舵机 |

### FR-V3 自然语言兜底理解（P0 必做，LLM 通道）

- 命令词没听过的说法（"往前挪挪""能不能坐一下""给爷走两步"）交给迁移后的 LLM 解析为动作符号
- 模型不理解时**明确拒绝并反馈**（蜂鸣两声/"没听懂"音效），**绝不猜一个相近动作执行**
- 模型输出中的动作名、参数由硬件校验层独立复核，超范围即拒绝

### FR-V4 语音反馈（P1 可选）

- 执行成功/拒绝/低电量有可区分的音效或语音提示
- 无扬声器时降级为蜂鸣器音效编码（1 声=执行，2 声=没听懂，3 声=拒绝/危险）

### FR-V5 遥控通道仲裁（P0 必做）

- 语音与 BLE 小程序遥控并存；**最新指令生效**，但"停"类命令优先级最高、任何通道任何时候都能急停
- BLE 小程序保留语音开关与命令日志页面（调试期用来看"它到底听成了什么"）

### FR-V6 声学体验约束（P0）

- 狗在走路/执行动作时收到语音命令：先停止当前动作再聆听（舵机噪声污染拾音）
- 低电压（<3.3V/cell）时语音功能降级为仅响应"停"，保护电池优先于听指挥

## 4. 非功能需求

| 编号 | 指标 | 目标值 | 备注 |
|---|---|---|---|
| NFR-V1 | 唤醒→命令词动作开始延迟 | ≤ 1.5 秒 | MultiNet 路径，实测为准 |
| NFR-V2 | 唤醒→LLM 路径动作开始延迟 | ≤ 3.5 秒 | 参照 gpio-llm 实测 150ms~1.5s 推理延迟 + 拾音时间 |
| NFR-V3 | 完全离线 | 不依赖 WiFi/手机/云端 | 唤醒、识别、理解、执行全在板上 |
| NFR-V4 | 域内口语句理解准确率（LLM 路径，手写保留集） | ≥ 85% | 英文版 84.4%、中文版 63.3%，需靠语料补齐 |
| NFR-V5 | 该拒绝却执行的比率（LLM 路径） | ≤ 5%，且**动了腿的误动作 ≤ 2%** | 硬件校验层兜底后统计口径 |
| NFR-V6 | Flash 占用 | app ≤ 4MB，模型分区 ≤ 3MB，LLM 权重 ≤ 2MB | 总 16MB，余量 > 60% |
| NFR-V7 | 固件稳定性 | 连续语音+行走联调 72h 无重启、无栈溢出 | 沿用固件工程纪律 |

## 5. 交付范围与不做的事

**做**：语音唤醒、命令词控制、LLM 兜底理解、动作执行、（可选）语音反馈、BLE 遥控并存。

**明确不做（v1 范围外）**：

- ❌ 对话/闲聊——模型只做"指令→动作"，不是语音助手（gpio-llm 原则：Not an assistant）
- ❌ 联网大模型兜底——保持全离线
- ❌ 自由度扩展（12DOF）——沿用 8 舵机布局
- ❌ 声源定位/声纹识别

## 6. 里程碑规划（语音线 V 系列，与运动线 M 系列并行）

| 里程碑 | 内容 | 前置条件 |
|---|---|---|
| V0 | INMP441 麦克风上板，录音回放/波形验证，引脚定稿 | 无 |
| V1 | 唤醒词 + 命令词（纯 MultiNet）驱动**单个舵机点动** | V0 + M0-2 舵机驱动 |
| V2 | 机器狗语料训练 + 三道门禁 + 全新手写保留集评测 | 无（可纯电脑端先行） |
| V3 | LLM 兜底链路上板，与 MultiNet 并联，串口可见解析结果 | V1 + V2 |
| V4 | 语音 × 全步态联调（依赖 M2 站立、M3 爬行），急停、仲裁、误触发测试 | V3 + M3 |

> 建议顺序：V0→V1 走硬件线尽早暴露引脚/内存问题；V2 纯软件可随时穿插；运动能力仍按原 M1→M2→M3 推进，两条线在 V4 会师。

## 7. 风险清单

| 编号 | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | 自定义唤醒词"小八小八"需乐鑫官方定制（收费/周期） | 唤醒词不可用 | 备选免费唤醒词（Hi ESP/Hi 乐鑫 等）；唤醒词在方案里是可替换插件 |
| R2 | 板内 SRAM 紧张：ESP-SR（AFE/WakeNet）+ BLE + 8 路 LEDC 同驻 | 功能冲突、分配失败 | V0 即做内存预算实测（heap 计量），BLE 与语音分时或降级单模 |
| R3 | LLM 中文保留集成绩仅 63.3%，迁移到动作域可能同样偏低 | NFR-V4 不达标 | 语料重建时专门补中文语序模板（副词前置、双分句）；把 V2 门禁设为独立里程碑，不达标先补语料再上板 |
| R4 | 舵机噪声污染拾音，走路时听不清命令 | 体验差 | FR-V6：动作中先停后听；结构上麦克风远离舵机、加硅胶减振 |
| R5 | 训练/语料磁盘占用 | C 盘常年紧张（0~2GB 可用） | 全部产物放 E:\gpio_llm 与 E:\esp，禁止落 C 盘 |
| R6 | 命令词与 LLM 输出动作集不一致导致"两套理解" | 维护混乱 | 单一事实源：动作符号表唯一定义，MultiNet 命令词表与语料生成脚本都从它派生（见设计文档 §4） |
