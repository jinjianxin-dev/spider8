# 08 · LED 与 PWM 电气验证（舵机未到货也能验）

> 适用阶段：M0-2 ｜ 前置：固件已烧写、串口能进 `spider8>` ｜ 日期：2026-11-04

> **这步解决什么问题**：舵机还没到货时，怎么确认"8 路 PWM 真的输出正确"，

## 0. 三十秒版

```
LED 长脚 → GPIO4（信号）     LED 短脚 → 220Ω → GND
串口执行：pwm 0 500     →  很暗
         pwm 0 2500    →  明显变亮（约 5 倍）
         pwmscan 0     →  由暗到亮再变暗，来回两次
         pwmscan all   →  8 个脚上的 LED 同步呼吸
```

三句话都成立，8 路 PWM 就是好的。

## 1. 为什么 LED 能代替舵机

舵机信号不是"电压高低"，而是**每 20ms 一个正脉冲**，靠脉冲宽度表示角度：

```
       ┌──┐                    ┌──┐               ← 3.3V
       │  │                    │  │
   ────┘  └────────────────────┘  └──────────     ← 0V
       │◄►│  脉宽 0.5~2.5ms
       │◄──────── 20ms ────────►│
```

- **频率 50Hz 是死的**，8 路都一样，永远不变
- **只有脉宽在变**：500µs = 一个极限角度，1500µs = 中位，2500µs = 另一个极限

LED 每秒被点亮 50 次、每次亮 0.5~2.5ms。人眼完全跟不上 50Hz，看到的是一条**连续的光**，
亮度正比于"亮的時間占比"（占空比）：

```
占空比 = 脉宽 ÷ 20ms
500µs  → 2.5%   很暗
1500µs → 7.5%   中等
2500µs → 12.5%  最亮（是 500µs 的 5 倍）
```

**关键认识**：占空比本身很低（2.5%~12.5%），所以 LED 天生就偏暗，这是正常的。
如果在明亮房间里看不清，把电阻换小一点，或者用手罩住 LED 遮光看。

这正是我们要的：脉宽变 → 亮度变。**亮度不动，就说明 PWM 没在按命令走。**

## 2. 材料

| 物料 | 数量 | 说明 |
|---|---|---|
| 发光二极管（LED） | 1~8 个 | 任意颜色，红色最省心（正向压降最低） |
| 电阻 | 1~8 个 | 单路测试用 **100~220Ω**；8 路同时点亮用 **470Ω~1kΩ**（见下） |
| 杜邦线 | 若干 | 母对母，插开发板排针 |
| （可选）万用表 | 1 台 | 有的话能读数字，比看亮度准得多 |

### 电阻怎么选（这一步别随便）

LED 正向压降约 2.0V，GPIO 输出 3.3V，所以：

```
峰值电流 = (3.3V - 2.0V) ÷ 电阻
```

| 电阻 | 峰值电流 | 单路平均电流（占空 7.5%） | 适用场景 |
|---|---|---|---|
| 100Ω | 13mA | 约 1.0mA | **只测一路**时用，最亮最好认 |
| 220Ω | 5.9mA | 约 0.44mA | 单路、或两路同时 |
| 470Ω | 2.8mA | 约 0.21mA | 8 路同时点亮 |
| 1kΩ | 1.3mA | 约 0.1mA | 8 路同时，最保守 |

- 单脚上限 40mA，**100Ω 也远没到**，安全
- 但 8 路是**同时**出脉冲的，总电流会叠加。8 × 13mA = 104mA 对 3.3V 稳压器压力偏大，
  所以同时点 8 个时用 470Ω 以上
- 用错电阻不会烧板子，最多是太暗或太亮看不清

## 3. 接线

```
   ESP32-S3 开发板
   ┌──────────────┐
   │              │
   │  GPIO4 ●─────┼──── LED ──── 220Ω ────┐
   │  (CH0/FL髋)  │      ▲长脚   ▲        │
   │              │      └短脚────────────┤
   │  GND   ●─────┼───────────────────────┘
   └──────────────┘
```

**极性**：LED 有两个脚，**长脚是阳极（+），短脚是阴极（−）**。
长脚接 GPIO，短脚经电阻接 GND。接反了不亮，但不会坏，翻过来就行。

**三条铁律**：

1. ❌ **不要接 5V 或舵机电源轨**。GPIO 只耐 3.3V，接 5V 会倒灌烧引脚。
2. ❌ **不要省掉电阻**。GPIO 直连 LED 的瞬态电流会超过 40mA 上限。
3. ✅ **必须共地**。LED 的地和开发板 GND 是同一个。

### 8 路引脚对照表

| 通道 | GPIO | 关节 | 通道 | GPIO | 关节 |
|---|---|---|---|---|---|
| CH0 | **4** | FL 髋 | CH4 | **15** | RL 髋 |
| CH1 | **5** | FL 膝 | CH5 | **16** | RL 膝 |
| CH2 | **6** | FR 髋 | CH6 | **17** | RR 髋 |
| CH3 | **7** | FR 膝 | CH7 | **18** | RR 膝 |

> GPIO4 在 M0-1 时是心跳 LED，现在已经是舵机 CH0 —— 看到它不再闪心跳是正常的。

## 4. 三个测试，从易到难

### T1 · 单通道固定脉宽

**目的**：确认某一路 PWM 存在，且脉宽随命令变化。

接好 CH0（GPIO4）后：

```
pwm 0 500
pwm 0 1500
pwm 0 2500
```

| 命令 | 占空比 | 期望现象 | 万用表 DC 读数 |
|---|---|---|---|
| `pwm 0 500` | 2.50% | 很暗，几乎看不见 | ≈ 0.083V |
| `pwm 0 1500` | 7.50% | 中等亮度 | ≈ 0.248V |
| `pwm 0 2500` | 12.50% | 最亮（是 500 的 5 倍） | ≈ 0.413V |

**判定**：亮度读数是**逐级递增**、万用表读数落在 ±0.05V 内 → 这一路合格。

> ⚠ 测试期间固件进入 raw 模式，**步态和姿态暂停**（`status` 顶部会显示警告）。
> 测完执行 `pwm off` 回到站姿，否则它会一直停在这个脉宽上。

---

### T2 · 8 路同时呼吸

**目的**：一次确认 8 路**都有**输出，且都在变化。

8 个脚各接一个 LED（470Ω 以上），然后：

```
pwmscan all
```

| 期望现象 | 说明 |
|---|---|
| 8 个 LED **同时**由暗变亮，再变暗，来回 2 次 | 同一路 LEDC 定时器，所以完全同步 |
| 全程约 6.4 秒 | 每步 25µs / 20ms，上下各 80 步 × 2 回 |
| 结束后自动回站姿 | 固件会自动 `servo_raw_exit` + 站立 |

**判定**：8 个 LED 亮度和节奏**完全一致**。有一个不亮 → 该通道有问题，
进 T3 定位。有一个节奏不同步 → 引脚接错了（接到别的 GPIO 去了）。

---

### T3 · 逐通道隔离

**目的**：验证"没有串到隔壁脚"，且 GPIO 映射表与实际一致。

只接一个 LED，轮流测 8 个脚：

```
pwmscan 0    → 只有 GPIO4 上的 LED 呼吸，其余 7 个脚必须完全不亮
pwmscan 1    → 只有 GPIO5 亮
pwmscan 2    → 只有 GPIO6 亮
... 一直到 pwmscan 7 → GPIO18
```

**判定标准（这条最严格）**：

- 该亮的亮
- **不该亮的绝对不亮** —— 如果 `pwmscan 3` 让 GPIO7 和 GPIO18 一起亮，
  说明两根线短接了，或者 `config.h` 里的引脚表填错了

最省事的做法：8 个 LED 全接上，然后 `pwmscan 0` 到 `pwmscan 7` 各跑一遍，
每次只该有一盏在呼吸。

## 6. 没有万用表时怎么读得更准

### 方法一：手机摄像头（零成本）

用手机相机对着 LED，屏幕上通常能看到**横向的明暗条纹或轻微闪烁**。
这是因为相机快门与 50Hz 不同步。**看到条纹 = 确实在 PWM，不是常亮**。

（不同手机快门策略不同，有的会自动消掉条纹，看到不闪不代表坏，只作为辅助判断。）

### 方法二：串一个电容当"峰值检波"

LED 两端并一个 10µF 电容（注意极性），LED 会变得更"稳"，亮度也更接近平均值。
不必要，纯属折腾。

### 方法三：万用表正确用法

- 挡位：**直流电压（DC V）**，选 **2V 或 20V 量程**
- 黑表笔接 GND，红表笔接信号 GPIO
- 读到的是平均电压 = 3.3V × 占空比

| 脉宽 | 理论读数 | 实测容差 |
|---|---|---|
| 500µs | 0.083V | ±0.05V |
| 1000µs | 0.165V | ±0.05V |
| 1500µs | 0.248V | ±0.05V |
| 2000µs | 0.330V | ±0.05V |
| 2500µs | 0.413V | ±0.05V |

> 读数偏低且不稳定是正常的：50Hz 下万用表采样点数少，加上 GPIO 驱动能力有限。
> **看趋势比看绝对值重要** —— 500 → 2500 读数应该单调上升约 5 倍。

## 7. 有示波器时（最权威）

探头接地夹接 GND，探针接信号脚，`pwm 0 1500`：

| 项目 | 期望值 |
|---|---|
| 周期 | **20.00ms**（50.0Hz），抖动应 < 100µs |
| 脉宽 | **1.500ms** ± 5µs（14bit 分辨率约 1.22µs/LSB） |
| 高电平 | 3.2~3.3V |
| 低电平 | < 0.1V |
| 上升沿 | < 1µs |

再执行 `pwm 0 500` / `2500`，脉宽应精确变成 0.500ms / 2.500ms。
**周期必须始终是 20ms 不变** —— 周期变了就是 LEDC 定时器配错了。

## 8. 异常排查表

| 现象 | 最可能原因 | 处理 |
|---|---|---|
| LED 完全不亮 | 极性接反 | 长短脚对调 |
| | 电阻太大 | 换 100Ω 试 |
| | 接错引脚 | 核对 §3 引脚表，用 `pwm all 2500` 一次全点亮 |
| | 命令没生效 | `status` 看是否显示"PWM 电气测试模式"；没显示说明命令没执行成功 |
| 一直亮、不闪不呼吸 | 接到了 3.3V / 5V 常电 | 确认接的是 GPIO，不是电源排针 |
| 亮度不随命令变化 | 走到别的通道去了 | `pwm all 500` 与 `pwm all 2500` 对比总亮度 |
| 8 路同时亮但单路不亮 | GPIO 表与实物不符 | 用 `pwmscan 0..7` 逐个定位，反查实际 GPIO |
| 扫完停在半亮不动 | 上一次扫描被中断 | `pwm off`，再 `pose stand` |
| 万用表读 0V | 用了交流档 | 切到 DC V |
| | 表笔没接好 | 直接量 GPIO 与 GND 之间 |
| 万用表读数一直 3.3V | 引脚被拉高但没输出 PWM | 检查 `pwm` 命令是否返回错误，`status` 确认模式 |

### 关于"扫完不回站姿"

`pwmscan` 结束时会自动退出 raw 模式并 `motion_stand()`。**`pwm` 不会** —— 它会一直保持
你给的那个脉宽，直到 `pwm off`。这是故意的：便于你用万用表慢慢量。

## 10. 360° 位置舵机的脉宽端点标定（2026-11-11 新增）

舵机到货后确认是 **360° 大行程**型号，端点可能超过 2500µs，因此裸脉宽通道
（`pwm` / `pwmscan` / `servo_raw_us`）的上限从 2500 放宽到 **3000µs**：

| 位置 | 常量 / 命令 | 改动 |
|---|---|---|
| `config.h` | `SERVO_US_CMD_MIN/MAX = 500/3000`、`SERVO_US_RAW_MIN/MAX = 300/3000` | 新增，统一裸脉宽范围 |
| `console.c` | `cmd_pwm` 校验、用法、`cmd_pwmscan` 的 `hi` | 改用宏 |
| `servo.c` | `servo_deg_to_us()` / `servo_raw_us()` 夹紧 | 改用宏 |
| `tools/servo_calib.html` ③ | 滑块、快捷值、自动扫描 | 扩到 500~3000µs |

50Hz 下 3000µs = 15% 占空比；PCA9685 12bit 计数 = 3000×4096/20000 ≈ 614，
远小于 4095，输出安全。**必须烧写这一版固件**，否则 `pwm 0 2900` 会被旧固件拒绝。

### 10.1 「1500µs 该是 90° 还是 180°？」

两者不矛盾，量的不是同一个东西：

- 固件里的「90°」是**内部刻度**（0~180 半量程），
  现为 `us = 1500 + (deg−90)×1200/180`（§10.3 之前是 ×2000/180）。
  固件只负责把内部角换算成脉宽，并不知道舵机轴物理上转了多少度。
- 若波段是 500~2500µs ↔ 0~360°，1500µs 在**物理上确实是 180°**；
  本机实测波段是 500~2900µs，1500µs 只对应 (1000/2400)×360 = **150°**，连物理中点都不是。

**装腿不必追求物理 180° 中点**：装配基准由我们人为定义 —— 把「腿站直」装在
1500µs，固件上电也发 1500µs（`SERVO_US_MID_DEFAULT`），两边一致就不会跳。
`tools/servo_calib.html` ③ 的「去实测中点」只用于观察物理中位，**不要拿它装腿**。

### 10.2 实测端点（2026-11-11 最终裁决）

**用户实测波段：500 ~ 2900µs ↔ 0~360°，跨度 2400µs。**

此前「500→2500µs 约转 330°」是目测值，和这个端点并不自洽：若端点真是 2900µs，
500→2500 只该转 2000/2400×360 = **300°**。目测角度误差、端点死区、非线性都可能造成偏差，
**以端点实测为准**；线性外推（标定台 ③ 的 📐 小工具）只用于「还没找到端点时估计往哪继续找」，
不能反过来推翻端点。

由此定死两个换算：

```
1° 物理角   = 2400µs / 360° = 6.667 µs
1500µs 对应 = (1500−500)/2400 × 360 = 150°（物理角，不是 180°）
```

1500µs 不是物理中点，但**装腿仍按 1500µs**（装配基准人为定义，固件 `us_mid` 也是 1500，
两边一致就不会跳）。「去实测中点」只用于观察，不拿来装腿。

### 10.3 角度映射已按实测修正（`us_span = 1200`）

要让「1° 关节指令 = 1° 物理转角」，条件是：

```
us_span / 180 = 实测跨度 / 360   →   us_span = 实测跨度 ÷ 2 = 2400 ÷ 2 = 1200
```

`config.h` 已把 `SERVO_US_SPAN_DEFAULT` 从 **2000 改成 1200**，
`SERVO_US_MID_DEFAULT` 保持 **1500**（端点没测准之前不改的原则已履行）。

| 项目 | span=2000（旧） | span=1200（现值） |
|---|---|---|
| 1° 指令发出脉宽 | 11.11µs → **1.667° 物理角** | 6.667µs → **1° 物理角** |
| 0~180 内部刻度 | 500~2500µs = 300° 物理 | 900~2100µs = 180° 物理 |
| 12°/20ms 限速 | 物理 1000°/s，超过 600°/s 会丢步 | 物理 600°/s，正好 MG90S 标称 |
| 软限位 0~180° | 物理放大 1.667 倍，会撞机身 | 与膝/髋设计范围一致 |

通用公式（换舵机时复用）：`us_span = 180 × 实测脉宽差 ÷ 实测转过角度`。

**NVS 只存 trim/dir，不存 us_span**：改配置重烧后数值不丢，但同一个 trim 产生的脉宽偏移
按 span 比例缩小，站姿会偏移。换算 `trim_new = trim_old × 旧span ÷ 新span = ×1.6667`
（固件 trim 上限已从 ±30° 放宽到 **±50°** = `SERVO_TRIM_LIMIT_DEG`，
本机旧 trim 最大 −26°，换算后 −43.3° 仍在范围内；若旧值 >30° 才会溢出，
那时需重插舵机臂或用滑块重调）。详见 `docs/13` §3。

| 若实测波段是 | 跨度 | 应设 span |
|---|---|---|
| 500~2500 | 2000 | 1000 |
| 500~2700 | 2200 | 1100 |
| **500~2900（本机）** | **2400** | **1200** |
| 500~3000 | 2500 | 1250 |

### 10.4 操作注意

- 测之前先点标定台的「🧭 判别舵机类型」，确认是位置舵机（A 类）。
- 别让舵机顶在 500 / 3000µs 超过几秒（堵转发热）；测完 `pwm off`。
- 停在 2500µs 以上再 `pwm off`，舵机会被 12°/拍 限速平滑拉回 1500µs 站姿
  （约 0.2 秒），属正常回位。
- 若端点顶到 3000µs 舵机还在转，需再把 `SERVO_US_CMD_MAX` / `SERVO_US_RAW_MAX`
  放宽并重烧。
