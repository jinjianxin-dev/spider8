# M1 检查清单：站姿调好 → 第一次让它动

> 更新日期：2026-11-11 ｜ 适用：360° 位置舵机 + PCA9685 后端
> 前置：8 路 trim/dir 已调好并 `save`，机械腿已按 1500µs 装到站立姿势。
> **本版结论：脉宽波段已实测 = 500~2900µs ↔ 0~360°，倍率已定 `us_span = 1200`。**

---

## 0. 一句话结论：站姿准 ≠ 能动

打个比方：站姿相当于"音量调到正好"，可一旦开口唱歌（腿开始摆），
固件那把"尺子"就量错了。

- 旧固件按**普通 180° 舵机**发指令：`SERVO_US_SPAN_DEFAULT = 2000`，
  即内部 0~180° 对应 500~2500µs，1° 指令发出 `2000/180 = 11.11µs`。
- 本机舵机是 **360°**：实测 **500~2900µs ↔ 0~360°**，
  1° 物理角只要 `2400/360 = 6.667µs`。
- 于是旧固件每 1° 指令，实际转 `11.11 / 6.667 = 1.667°` 物理角。

后果（**改之前不要发**这些命令）：

| 命令 | 为什么会出事 |
|---|---|
| `walk` / `trot` | 步幅、抬脚全部按 1.667 倍放大，腿甩过头撞机身、绊腿 |
| `demo` / `pose crouch` / `pose lie` | 蹲下/握手的角度同样放大，可能顶死结构 |
| `pwmscan` | 接上舵机后全行程扫描，必堵转（文档 09 已列禁令） |

还有一条隐藏风险：限速 `SERVO_MAX_STEP_DEG = 12°/拍` 按**内部角**算，
旧 span 下物理等于 12×1.667 = 20°/20ms ≈ **1000°/s**，超过 MG90S 的 600°/s，
舵机会丢步。`span=1200` 时这个值正好回到 **600°/s**。

**站姿为什么没事**：站姿时 `(关节角 − 基准角) = 0`，倍率乘在 0 上，
所以怎么量都是对的；trim 只是把这一个点挪准了。一旦腿要动，误差立刻出现。

## 2. 定倍率（已完成，此处存档推导）

### 2.1 实测数据裁决了早期矛盾

**用户 2026-11-11 实测：500 ~ 2900µs 转满 360°，跨度 2400µs。**

早期「500→2500µs 约转 330°」是目测值，与端点不自洽：若端点为 2900µs，
500→2500 只应转 `2000/2400×360 = 300°`。目测误差、端点死区都可能造成偏差，
**以端点实测为准**；线性外推只用于「还没找到端点时估计往哪继续找」。

```
1° 物理角   = 2400µs / 360° = 6.667 µs
1500µs 对应 = (1500−500)/2400 × 360 = 150°（物理角，不是 180°）
```

### 2.2 公式与结果

```
要 1° 关节指令 = 1° 物理角：us_span / 180 = 2400 / 360
                          → us_span = 2400 ÷ 2 = 1200
通用公式：us_span = 180 × 实测脉宽差 ÷ 实测转过角度
```

`config.h` 已把 `SERVO_US_SPAN_DEFAULT` 从 **2000 改成 1200**，
`SERVO_US_MID_DEFAULT` 保持 **1500**（装腿基准不变，**不用拆腿重装**）。

| 项目 | span=2000（旧） | span=1200（现值） |
|---|---|---|
| 1° 指令发出脉宽 | 11.11µs → 1.667° 物理角 | 6.667µs → 1° 物理角 |
| 0~180 内部刻度 | 500~2500µs = 300° 物理 | 900~2100µs = 180° 物理 |
| 12°/20ms 限速 | 物理 1000°/s（丢步） | 物理 600°/s（MG90S 标称） |
| 软限位 0~180° | 物理放大 1.667 倍 | 与膝/髋设计范围一致 |

裸脉宽上限 `SERVO_US_CMD_MAX/RAW_MAX = 3000` 仍大于新映射的最大 2100µs，
`pwm 0 2900` 端点复测不受影响。**改动只涉及 `config.h` 一个常量**，编译零错误。

## 3. 重烧后必须处理 trim（最容易漏的一步）

固件映射是：

```
舵机内部角 = 90 + (关节角 − 站立基准角) × dir + trim
脉宽       = 1500 + (内部角 − 90) × us_span / 180
           = 1500 + trim × us_span / 180        （站姿时）
```

- **好消息**：`servo_save_cal()` 往 NVS 里只写 `trim` 和 `dir`，
  **不写 us_span / us_mid**。所以改 `config.h` 直接生效，**不用清 NVS，数值不丢**。
- **要注意**：span 从 2000 缩到 1200 后，同一个 trim 的脉宽偏移缩小到 60%，
  站姿会偏。例如 trim=+5°：原来 +55.6µs → 改后 +33.3µs，物理差约 3.3°。

### 3.1 换算（推荐先走这条）

```
新 trim = 旧 trim × 旧 span ÷ 新 span = 旧 trim × 2000/1200 = ×1.6667
```

标定台 ⑤ 新增「🔄 改 us_span 后的 trim 换算」折叠面板，默认 2000 → 1200：

1. 烧写新固件后重新连接标定台；
2. 点「📋 读取板子状态」→ 8 路旧 trim 填进快照和换算表；
3. 点「写入换算值 + save」→ 自动发 8 条 `trim` + `save`。
   **换算后脉宽不变，舵机不该跳。**

**本机 2026-11-11 读回的真实 trim 与换算结果**（`status` 8 路，dir 全 +1）：

| CH | 关节 | 旧 trim | ×1.6667 后 | 备注 |
|---|---|---|---|---|
| 0 | FL 髋 | −25.0° | **−41.7°** | 超原 ±30° 上限 |
| 1 | FL 膝 | +18.0° | **+30.0°** | 正好压原上限 |
| 2 | FR 髋 | −23.0° | **−38.3°** | 超原 ±30° 上限 |
| 3 | FR 膝 | +18.0° | **+30.0°** | 正好压原上限 |
| 4 | RL 髋 | −26.0° | **−43.3°** | 最大一只，超原 ±30° 上限 |
| 5 | RL 膝 | +17.0° | **+28.3°** | |
| 6 | RR 髋 | −23.0° | **−38.3°** | 超原 ±30° 上限 |
| 7 | RR 膝 | +18.0° | **+30.0°** | 正好压原上限 |

因此把 `config.h` 的 `SERVO_TRIM_LIMIT_DEG` 从 30 放宽到 **50**（`servo.c`、`console.c`、
标定台滑块 / 换算面板同步）。这只是软件夹紧量：换算后脉宽仍 900~2100µs 区间内、
站姿 `sv` 仍 46.7~120° 都在 0~180° 硬限位内，动作幅度不变。
**代价**：大 trim 会吃掉一侧硬限位余量，若 `clampN` 增长就调小 `stride` / `lift`。
更彻底的根治是拆下 8 只舵机臂、在 1500µs 重新插到站姿，让 trim 回到几度——但那要重做一遍标定，非必要。

工具用快照做源，重复点不会累积放大；若某路换算后仍超 ±50°（面板标红），
只能把舵机臂拔下重插到 1500µs 站姿，或用 ④ 滑块重新对齐。

**2026-11-11 执行结果（已完成，勿重复）**：助手通过串口一次发完 8 条 `trim` + `save`，
回显 `标定值已保存: ESP_OK`，`status` 复核 8 路为
`−41.7 / +30.0 / −38.3 / +30.0 / −43.3 / +28.3 / −38.3 / +30.0`（dir 全 +1）。
换算前后站姿脉宽差 <0.3µs（例 CH0：1222.2 → 1222.0µs），舵机不跳。
`status` 能显示 −41.7° 本身也证明新固件的 ±50° 上限已生效（旧固件会夹到 −30°）。
**所以标定台 ⑤ 的「写入换算值」按钮不要再点第二次**（面板已加确认框与红字警告）。

### 3.2 更稳的做法

重烧后用 ④ 重新拖一遍 8 路滑块，肉眼看腿回到站姿，再点 ⑤「保存」。
反正工具现成，也顺便复核了 dir。

> ⚠ 顺序提示：**先烧写、再换算**。若在旧固件上提前把新 trim 写进 NVS，
> 板子会以 span=2000 放大这组值，站姿先偏一次，虽然重烧后会恢复，但没必要。

## 4. 空走验收：把狗架起来，四脚悬空

**别一上来就放地上。** 用书/盒子把机身垫高，让四条腿自由摆动。

### 4.0 命令速查表（板子上已注册的全部命令，2026-11-13 更新）

**蹲下就是 `pose crouch`；站起来是 `pose stand`（`stop` 等价）。** 姿态名的拼写必须完全一样，写错会回 `未知姿态: xxx`。

| 分类 | 命令 | 作用 / 参数 | 备注 |
|---|---|---|---|
| 姿态 | `pose stand` | 站直（默认姿态：膝 −48° / 髋 24°） | 900ms 缓动，脚不前后滑（见 §4.6）；站姿可调，见 §4.7 |
| 姿态 | **`pose crouch`** | **蹲下**（膝 −70° = 站姿 −22°） | 最安全的第一个动作 |
| 姿态 | `pose lie` | 趴下（膝 −95°） | 膝软限位是 −100°，第一次别在地面试 |
| 姿态 | `pose shake` | 握手（右前腿抬起 34mm + 前伸 22mm） | 2-DOF 只能"往前递爪"，不能真横向伸 |
| 姿态 | `pose wave` | 挥手（右前腿 1.2Hz 上下摆） | 会一直摆到切换别的姿态 |
| 动作 | `demo` | 蹲 → 站 → 握手 → 挥手，约 9 秒自动回站姿 | ⚠ **演示期间串口被占住 9 秒**，敲命令没反应不是死机 |
| 行走 | `walk [0-100]` | 四拍波步；参数是**速度百分比**，不是步数 | 会一直走，直到 `stop`；**首试 `walk 100`**（见下方警告）；换动作先回站姿，见 §4.8 |
| 行走 | `trot [0-100]` | 对角小跑（更快、更不稳） | 等 `walk` 稳了再试；`trot→walk` 不再顿挫（§4.8） |
| 行走 | `stop` | 停止并回站姿，同时把转向归零 | 随时可用；`pose stand` 等价 |
| 行走 | **`left` / `right`** | **原地左转 / 右转**（差速 ±70%） | 2-DOF 腿不能横向跨步，只能靠左右步幅差动；`straight` 回正 |
| 行走 | `straight` | 转向回正 + 恢复直行（速度 100%） | 从原地转直接过渡到前进，也经站姿中转 |
| 调参 | `speed <0-100>` | 前进速度 | 一次只改一个参数 |
| 调参 | `turn <-100..100>` | 差速转向**持续偏置** | 设了会一直转；临时转一下用 `left`/`right`，`stop` 会归零 |
| 调参 | `period <800-3000>` | 步态周期 ms，默认 1200 | 舵机跟不上就加长 |
| 调参 | `stride <8-30>` | 步幅半幅 mm，默认 22 | `clampN` 涨就调小 |
| 调参 | `lift <6-26>` | 抬脚高度 mm，默认 14 | 调大会让峰值角速度超 600°/s |
| 调参 | `duty <10-45>` | 摆动相占空比 %，默认 25 | |
| 调参 | **`posedur <200-3000>`** | **姿态过渡时长 ms，默认 900**；不带参数 = 查询，0 = 恢复默认 | 蹲/趴太快或太慢就现场调，不用重烧 |
| 调参 | **`fadedur <200-2000>`** | **收脚/起步淡入淡出时长 ms，默认 500**；不带参数 = 查询，0 = 恢复默认 | 管「回站姿」和「起步」，与 `posedur` 分开；只影响下一次切换 |
| 调参 | **`standhold <100-2000>`** | **站姿停留时长 ms，默认 300**；不带参数 = 查询，0 = 恢复默认 | 回站姿后等舵机真正站稳再切下一个动作；只影响下一次切换（§4.9） |
| 调参 | **`standknee <-70..-30>`** | **站姿屈膝角，默认 −48°**；不带参数 = 查询，0 = 恢复默认 | 负值越大腿越弯、机身越低；髋自动 = −膝/2，**trim 不用重标**（§4.7） |
| 诊断 | `status` | 模式 / 参数 / 峰值角速度 / 8 路角度 / `clampN` / 堆与栈余量 | 每轮动作前后都发一次 |
| 诊断 | `help` | 列出所有命令（ESP-IDF console 内置） | 忘了拼法就敲它 |
| 诊断 | `pcadiag` | 读回 PCA9685 寄存器 | 只在怀疑接线/芯片时用 |
| 标定 | `cal <0-7> <角度>` / `cal off` | 单关节手动点动 | 用完必须 `cal off` |
| 标定 | `trim <0-7> <-50..50>` / `dir <0-7> <1\|-1>` / `save` | 站姿微调 / 方向 / 写 NVS | 已完成，别再动 |
| 电气 | `pwm <0-7\|all> <500-3000>` / `pwm off`、`pwmscan` | 裸脉宽 | ⚠ 腿已装好，**禁止带腿扫描/顶端点**；若上一条 `pwm` 没 `off`，所有姿态命令都不会生效 |

**关节软限位**：髋 −45°~+75°、膝 −100°~+8°；`12°/拍` 限速（≈600°/s）负责平滑过渡。超限时 `status` 里的 `clampN` 会涨。

| 顺序 | 命令 | 看什么 |
|---|---|---|
| 4.1 | `status` | 「峰值角速度」应 ≤600°/s 且有余量；`clampN` 应为 0（没撞软限位） |
| 4.2 | `demo` | 蹲 → 站 → 握手 → 挥手约 9 秒。动作幅度温和，先确认 8 路方向都对、没有一只反着转 |
| 4.3 | **`walk 100`** | 满速波步，看四拍相位是否协调、腿有没有互绊、机身有没有往前挪；随时 `stop` |
| 4.4 | `speed` / `stride` / `lift` / `duty` | 只在 4.3 稳定后再微调，一次只改一个参数 |

> ⚠ **首试别用 `walk 20`（早期清单这里写错过）**：`speed_pct` 线性缩放**步幅**，
> 但**不缩放抬脚高度**。PC 单测（gcc 直编 `gait.c`，从真实输出角度反算脚轨迹）实测：
>
> | speed | 脚前后范围 | 支撑相位移 | 抬脚峰值 | 理论净前进 |
> |---|---|---|---|---|
> | 0% | ±0.00mm | 0 | 13.87mm | 0（**设计上就是原地踏步**） |
> | 20% | ±4.40mm | +4.40 → −4.17mm | 13.87mm | 8.8mm/周期 ≈ 7.3mm/s |
> | 60% | ±13.20mm | +13.20 → −12.51mm | 13.87mm | 26.4mm/周期 |
> | 100% | ±22.00mm | +22.00 → −20.85mm | 13.87mm | 44.0mm/周期 ≈ 36.7mm/s |
>
> 20% 时脚抬 14mm 却只挪 4.4mm，肉眼就是「原地高抬腿」；再被舵机齿隙、
> 乐高结构间隙和地面打滑吃掉，几乎看不出位移。要调慢请调 `period`（加长周期），
> 不要用很小的 `speed`。

供电提醒：舵机启动瞬间 0.5~1A，**带载电压不能掉到 4.8V 以下**
（11-10 已确认电池盒带载不足会让 8 只全不动）。发命令时盯一下舵机红线对棕线。

| 现象 | 判断 / 处理 |
|---|---|
| 腿摆幅仍明显偏大、或舵机跟不上节奏 | span 还偏大，回第 2 步复测端点 |
| 只有某条腿方向反 | 先 `cal off` 回站姿，再 `dir <通道> -1`，`save` |
| 舵机抖一下就停 / 全部不动 | 先验带载电压，别回头怀疑固件 |
| `clampN` 一直涨 | 步幅超腿长，调小 `stride` / `lift` |
| **四只脚都在做走的动作，机身却不前进** | 见 §4.5，按顺序排查 |

### 4.5 「四脚都在走、机身原地」排查顺序（2026-11-11 用户实测现象）

**固件侧已排除**：`gait.c:223-226` 支撑相 `y = stride − 2·stride·u`，脚相对机身
从 **+stride 匀速移到 −stride**；脚抓地时反作用力把机身往前推，方向正确。
`gait.h` 里 `speed_pct=0` 的注释也写明「0 = 原地踏步」是**有意设计**。
PC 单测从 `gait_step` 真实输出的髋/膝角反算脚轨迹，确认支撑相位移与理论值一致
（见 §4.3 表格）。所以这不是步态算法的 bug，按下面顺序查物理与参数：

1. **是不是还四脚悬空？** §4 开头要求垫高机身做空走验收；悬空时脚蹬不到地，
   没有任何反作用力，机身**必然**原地不动 —— 这是正确现象，不是故障。
   撤掉垫块、四脚均匀着地再试。
2. **速度太小**：`walk 20` ≈ 8.8mm/周期，改敲 **`walk 100`**（44mm/周期）。
   同时 `status` 确认 `转向 = 0%`（`turn ≠ 0` 会原地打转）与 `clampN = 0`。
3. **地面太滑**：这套 2-DOF 腿靠脚底静摩擦推进，塑料脚在光滑桌面会打滑。
   换粗糙表面或脚底贴橡胶，先用 `walk 100` 看有没有位移。
4. **左右/前后腿方向互相抵消**（最隐蔽）：装配时舵机镜像安装，若某几路 `dir` 该翻没翻，
   一条腿往前迈、另一条往后蹬，四脚动作看着都很热闹但互相顶住。
   判别（每步都要回站姿）：
   ```
   stop → cal 0 30   看左前髋是不是向前摆 → cal off
        → cal 2 30   看右前髋是不是向前摆 → cal off
        → cal 4 30 / cal 6 30   两条后腿髋同样检查
   ```
   站姿髋 19°，给 30° 应该统一**朝狗头方向**摆。某路反了，安全序列：
   `pwm off` → `cal off` → `pose stand` → 等 ≥600ms → `dir <通道> -1` → `save`。
   ⚠ 不在站姿时翻 dir 会把腿镜像甩过去（见项目记忆「改 dir 前必须回站姿」）。
5. 以上全过仍不前进 → 量带载电压、确认 8 路舵机没丢步，再回报现象。

### 4.6 `pose lie` 大腿猛地下去、发抖、小腿后动 —— 已定位并修复（2026-11-11）

**用户实测现象**：`walk 100` 已能正常前进；但 `pose lie` 时「大腿下去不缓慢、有点抖，
大腿到一定角度后小腿才比较正常地下来，整体很不自然」。

**根因不是速度参数，是过渡路径的几何错误。** 站→趴的关节行程是
「髋 19°→47.5°（+28.5°）/ 膝 −38°→−95°（−57°）」，比例恰好 **1:−2**。
旧 `motion.c` 把 8 个关节角各自按 `11°/拍`（550°/s）等速逼近目标，于是：

| 拍 | 髋 | 膝 | 脚前后位移 | 说明 |
|---|---|---|---|---|
| 0 | 19.0° | −38.0° | 0mm | 站姿 |
| 1 | 30.0° | −49.0° | **+9.6mm** | 比例已破坏 |
| 2 | 41.0° | −60.0° | **+18.2mm** | 脚往前滑 |
| 3 | **47.5°（到位停住）** | −71.0° | **+18.6mm** | 髋只用 60ms 就冲到位 |
| 4 | 47.5° | −82.0° | +9.4mm | 髋不动、膝还在走 |
| 6 | 47.5° | −95.0° | 0mm | 才回到正确比例 |

两条腿等长时 `髋 = −膝/2` 才能保证脚在髋点正下方。等速插值破坏了这个比例，
四只脚在地面上**前滑 18mm 再滑回来**，加上髋 60ms 冲到位后突然停住、
起步/刹车的速度阶跃冲击齿轮 —— 就是「猛、抖、分段、不自然」的全部来源。

**修复**（`motion.c` / `config.h` / `console.c`）：姿态过渡不再逐关节插值，改成
**只用「膝角」一个标量做 smoothstep 缓动（默认 900ms），髋角每拍由
`gait_solve_static()` 反解**。这样比例恒成立、髋膝天然同步、脚前后位移恒为 0，
机身纯垂直升降；首尾角速度趋于 0，起步刹车不冲击。实测对比：

| | 旧实现 | 新实现 |
|---|---|---|
| 脚前后最大位移 | **+18.6mm** | **0.00mm** |
| 峰值膝角速度 | 550°/s（阶跃） | ≈95°/s（smoothstep） |
| 髋/膝到位时间 | 60ms / 120ms（不同步） | 同时，900ms |
| 过渡总时长 | 120ms | 900ms（可调） |

`posedur <200-3000>` 可现场调手感：`posedur 1500` 更慢更柔，`posedur 400` 更利落；
`posedur` 不带参数查当前值，`posedur 0` 恢复默认 900ms。**不用重烧。**
`status` 会打印当前「姿态过渡 xxxms」。

回归测试（PC 直编 `gait.c`，不需要板子）保留了这次的定量证据，
以后改姿态过渡可以随时重跑：

```bash
# 在工程根目录执行；本机 gcc 在 E:\gpio_llm\tools\w64devkit\bin
E:/gpio_llm/tools/w64devkit/bin/gcc.exe -O2 -I firmware/main \
    -o tools/fw_test/test_pose.exe tools/fw_test/test_pose.c firmware/main/gait.c -lm
./tools/fw_test/test_pose.exe        # 5 项断言，退出码 0 = 全过
```

中途打断也安全：`pose_begin()` 把过渡起点取为**当前插值中的实际膝角**，
所以趴到一半敲 `pose stand` 会平滑折返，不会跳回站姿。握手/挥手的单腿偏移
用同一个 smoothstep 系数 0→1 渐入、1→0 收回。

> ⚠ 这轮只动了 `pose` 过渡路径，`walk` / `trot` 的步态引擎**一行没改**，
> 所以 §4.5 已经验收通过的 `walk 100` 不受影响。

### 4.7 站立太直 → 腿再弯 10°（2026-11-13 已烧写验收）

**现象**：站姿四条腿看着太直，想让髋和膝都再弯一点。

**不能直接各弯 10°**：两连杆等长时，脚要落在髋点正下方 ⇒
`髋角 ≡ −膝角/2`（`gait_hip_for_knee()` 的严格性质）。膝从 −38° 折到 −48°
时，髋只能跟着从 19° 到 24°（+5°）。硬让髋也 +10°，四只脚会整体前移
8.7mm，重心跑出支撑面、站着往后栽 —— 和 §4.6「髋膝必须 1:2 同步」是同一条铁律。

**最容易踩的坑**：`GAIT_STAND_KNEE_DEG = -38°` 原本同时是
① 装配基准（装腿时 1500µs+trim 对应的腿姿）和 ② 默认站姿。
`servo.c` 用它当 `s_ref_joint`：`sv = 90 + (目标角 − 装配基准) × dir + trim`。
**只把这个宏改成 −48°，站姿时「目标角 = 基准角」，sv 仍是 90+trim，
舵机脉宽一模一样、腿纹丝不动**，只是软件给同一个姿势改了个名字，
还会让 IK 的身高模型与实物差 3.5mm。

**正确做法：把两个概念拆开**（`config.h`）：

| 宏 | 值 | 含义 |
|---|---|---|
| `GAIT_STAND_KNEE_DEG` | −38° | **装配基准 = trim 零点，永远不要改** |
| `GAIT_DEFAULT_STAND_KNEE_DEG` | −48° | 上电 / 站立 / 步态的默认站姿 |
| `GAIT_STAND_KNEE_MIN/MAX` | −70 / −30 | `standknee` 在线可调范围 |
| `POSE_CROUCH_DK / POSE_LIE_DK / POSE_KNEE_FLOOR` | −22 / −47 / −95 | 蹲/趴相对站姿的增量与最深下限 |

装配基准不动 ⇒ 舵机相对零位多走「膝 −10°、髋 +5°」，腿真的弯下去，
**8 个 trim 一个都不用重标，NVS 不用动，不要去点标定台的换算按钮**。

**蹲/趴改成相对量**：以前是绝对值 −60°/−95°，站姿一改就会出现
「站得比蹲还低」。现在 `crouch = 站姿 −22°`、`lie = 站姿 −47°`，
并夹在 −95°（膝软限位 −100°）以内。默认站姿下蹲 −70°、趴 −95°，
趴下动作与旧版完全一致。

**现场微调**（不用重烧）：

```text
standknee            # 查询：膝 −48.0° / 髋 24.0° / 髋轴离地 100.5mm
standknee -58        # 更弯（膝 −58° / 髋 29°），髋自动跟
standknee -38        # 回到原来的站姿高度（即装配基准姿势）
standknee 0          # 恢复默认 −48°
```

改完会重新起步一次 900ms 缓动，腿平滑弯下去而不是瞬跳；`walk` 模式下
下一拍 `gait_step()` 直接用新值，由 11°/拍 斜率限制兜底。

**验收**（烧写后 `status` 实测）：

```text
站姿 膝 -48.0° / 髋 24.0°  髋轴离地 100.5mm（standknee 可调，装配基准 -38° 不变）
峰值角速度 ≈ 418°/s（MG90S 600°/s，余量 30%）  ✓
 0 FL 髋 24.0° 舵机 53.2°  +1 trim -41.7°   ← 原 48.3°，+4.9°
 1 FL 膝 -48.0° 舵机 109.9° +1 trim +30.0°   ← 原 120.0°，−10.1°
```

8 路 trim 与 11-11 保存的值完全一致，`clampN` 未触发。机身从 104.01mm
降到 100.49mm（−3.52mm），脚前后位移 0.0000mm。腿更弯后 `dh/dknee`
变大，抬同样 14mm 所需角度更小，峰值角速度由 477°/s 降到 418°/s，
余量从 21% 提到 30%。

**顺带修掉的回归**：旧版「改 `dir` 前回站姿就安全」依赖「站姿差值 = 0」
（`dir` 乘 0，翻转不改变 sv）。站姿改成 −48° 后差值是 −10° / +5°，
直接翻转会让 sv 突变 +20° / −10°，8 路一起刷新就是整机猛地一甩。
`servo_set_dir()` 现在按「保持当前输出脉宽不变」反解新 trim：
`trim_new = s_servo − 90 − d × dir_new`（`d = 当前关节角 − 装配基准`），
用最近真正下发的 `s_servo` 把限速 / 硬限位历史一并吸收。
**翻转瞬间不驱动舵机，但 trim 数值会变，记得 `save`。**

**回归**：`tools/fw_test/test_gait.c` 新增 Q7（6 项断言），
`test_pose.c` 5 项照旧全过。固件 `spider8.bin` 约 947 KB，
3MB OTA 槽剩 70%，零编译告警。

### 4.8 一切换先回「中间态站姿」+ 补齐左右转（2026-11-13）

**用户实测现象**：从站立开始 `walk` 正常；从 **蹲 / 趴** 直接 `walk` 会「乱套」；
**`trot → walk`** 过渡不流畅；另外「向左向右的功能好像还没有」。

**三个现象其实是同一个根因：旧版 `motion_walk()` 是硬切。**

```text
旧：s_tick = 0; s_mode = MODE_WALK;   // 下一拍立刻输出「站姿膝角 + 满步幅」
```

| 起点 | 当前膝角 | 目标首拍膝角 | 一拍内差值 | 后果 |
|---|---|---|---|---|
| 站立 | −48° | ≈ −48° | ≈ 0° | 正常（所以只有站姿起步没问题） |
| 蹲下 | −70° | ≈ −48° | 22° | 髋膝各按 11°/拍 被拉回，破坏 1:2 几何 |
| 趴下 | −95° | ≈ −48° | 47° | 四脚在地面打滑好几拍 → 「乱套」 |

`trot → walk` 则是两套相位表（trot `{0,128,128,0}` / walk `{64,192,0,128}`）
硬切 + 相位清零，等于四条腿同时瞬移，再被限速闸拉回来 → 顿挫。
**这和 §4.6 的 `pose lie` 是同一类几何病，只是发生在模式切换而不是姿态缓动里。**

**方案（按用户要求）：所有切换都先经过「中间态站姿」这个道岔。**

```text
请求 walk / pose / stop
   ↓
① 回站姿：WALK → 步幅/抬脚淡出到 0；POSE → 膝角 smoothstep 收回站姿
   ↓        （挂起目标动作；中途再下命令只改「下一站」，不重启收脚）
② 站姿停留：保持纯站姿输出，等输出收敛 + 机械停稳（默认 300ms，见 §4.9）
   ↓
③ 站稳后执行：POSE → 从站姿 900ms 缓动到目标
              WALK → 相位清零、步幅从 0 淡入 500ms
              stop → 停在站姿
```

关键几何前提由 `gait_apply_fade()` 保证：**fade=0 时 `speed_pct=turn_pct=0`，
`gait_step()` 四脚 `y=0 / lift=0`，输出与 `gait_solve_static(站姿)` 逐位相同**。
所以相位清零、换步态、切模式的那一瞬间姿势完全连续，零跳变。
PC 单测 `tools/fw_test/test_transition.c` Q2 实测：
全周期最大前后偏移 **0.0000mm**、最大抬脚 **0.0000mm**、与 POSE_STAND 差 **0.000000°**。

- 淡出用「进入过渡那一刻」的参数快照 `s_trans_params`，
  中途拖 speed/turn 滑块或按 `left` 不会污染正在收脚的动作。
- 每次过渡的时长在进入时冻结到 `s_trans_dur_ms`，
  中途改 `posedur`/`fadedur` 只影响下一次切换，不会把淡出突然截断。
- `stop`/`pose stand` 顺手把 `turn_pct` 归零，避免转向偏置带进下一次起步。
- `status` 新增「动作切换 就绪 / 回站姿中 / 站姿停留中 / 起步淡入中 · 目标 xxx」；
  无线 `/api/status` 加 `trans` / `hold` 字段，网页状态栏能看到过渡阶段与停留时长。

**左右转的两个真缺口（一并修掉）**

1. **原地转不了**：旧公式 `stride = stride_mm × speed_k × (1 ± turn_k×0.6)`，
   `speed=0` 时整条 stride 被乘成 0，`turn` 完全失效。现改为
   `前进分量 + 自转分量` 相加：`stride = stride_mm×speed_k ± stride_mm×turn_k×0.6`。
   `speed=100` 时与旧公式**逐位相同**（已验收的 `walk 100` 不受影响）。
2. **没有一键左/右**：以前只有 `turn` 这个持续参数，设了 60 就一直转。
   新增 `left` / `right` / `straight`，网页控制台也加了三个按钮。
   ⚠ **2-DOF 腿不能横向跨步**，「向左向右」只能是**原地差速转向**（左侧步幅大、
   右侧小 → 右转），不是平移。

**顺手修掉的老毛病**：抬脚原来恒为 `lift_mm = 14mm`，与步幅无关，
所以 `walk 20` 前后只走 4.4mm 却抬 14mm，看着像「原地高抬腿」（§4.5 曾当成
正常现象）。现在 `lift ×= min(1, |实际步幅| / stride_mm)`：
`speed=0` 抬脚 **0.00mm**、`20%` 抬 **2.77mm**、`100%` 仍是 **13.87mm**。
`walk 100` 峰值角速度 **418°/s**、净推进 **44.0mm/周期**，一点没变。

**验证**：`test_transition.c` 15 项全过（fade=1 逐位一致、fade=0 纯站姿、
淡入相邻拍最大 7.21° ≈ 361°/s < 550°/s 限速、turn 反号四脚镜像误差 0.0000mm、
抬脚缩放、`walk 100` 回归）；`test_gait.c` / `test_pose.c` 全部照旧通过；
固件 `spider8.bin` **950,512 B**，零编译告警，3MB 槽剩 70%。

**上板验收顺序（一个动作一个动作确认，四脚悬空）**

```text
standhold           → 查询，应显示 300ms
pose lie            → 等趴稳
walk 100            → 缓缓站起 → 明显停一下 → 再起步，整个过程不再乱套
stop
trot 100            → 跑起来
walk 100            → 先收脚、停稳、再换成走，不应顿一下
stop
left / right        → 应原地打转（左侧步幅大 = 右转）
straight            → 回正并直行
standhold 600       → 再切一次动作，停留更久、更稳；standhold 0 恢复默认 300
fadedur 800         → 收脚更慢更柔；fadedur 0 恢复默认 500
```

⚠ **换动作现在会有约 0.8~1.7 秒延迟**（站姿起步 = 淡入 500ms；
走路换走路 = 淡出 500 + 停留 300 + 淡入 500ms；
趴下起步 = 回站姿 900 + 停留 300 + 淡入 500ms）。
这是刻意的，不是卡死；`status` 里能看到当前在哪个阶段。
急停 `/api/stop` 也走这条平滑收脚路径（500ms 内步幅渐减），不会硬跳。

### 4.9 回站姿后必须「停留」，等真正站稳再切动作（2026-11-13 二次实测修复）

**用户实测现象**：加了中间态站姿之后「有时候还会乱套」，观察发现是
「还没有真正的站稳，就开始下一个动作了」。

**根因：计时到 ≠ 站稳。** 上一版 `TRANS_TO_STAND` 的计时一结束，就立刻
`mark_stand_settled()` + `execute_pending()`，只等了**指令曲线走完**，
没等两件物理上的事：

1. `s_out`（真正送到舵机的 8 路关节角）被 `rate_limit` 限在 11°/拍，
   淡出 / 膝角回位途中可能还落后站姿几度；下一拍目标马上换成新动作，
   两段角速度叠加，又破坏髋膝 1:2 ⇒ 四脚打滑。
2. MG90S 是 0.1s/60°，PWM 指令到位后机械还要几十毫秒才停稳，再加齿隙
   回弹与四脚着地后的机身晃动 —— 肉眼就是「没站稳就又动了」。

**修复**：`TO_STAND` 结束后插入 `TRANS_SETTLE` 阶段，整段保持纯站姿输出，
必须**同时**满足两个条件才放行挂起的动作：

| 条件 | 判据 | 默认值 |
|---|---|---|
| 时间够 | `s_settle_ms >= standhold` | 300ms |
| 输出收敛 | 8 路 `s_out` 与站姿几何偏差 < 0.5°，且**连续 3 拍**（60ms） | — |

另有 `guard` 超时兜底：超过 `standhold + 800ms` 仍未收敛会打日志并强制放行，
避免舵机卡住时把狗永久锁在站姿。

- 新命令 `standhold <100-2000>`（`0` = 恢复默认 300）。和 `fadedur` 一样，
  时长在进入本次停留时冻结到 `s_settle_dur_ms`，中途改不会打断。
- 停留期间又下命令：只换挂起目标并重新计一次停留窗口，**不跳过停留**；
  `stop` 不重置计时，急停不被拖延。
- `status` 阶段显示「站姿停留中」，并多一行「站稳停留 300ms」；
  无线 `/api/status` 增加 `hold` 字段，网页状态栏显示。
- 从稳定站姿直接出发（上电后第一条命令）**不**播停留，不凭空多等 300ms。

**PC 单测 `tools/fw_test/test_settle.c`**：用桩把**真实的 `motion.c`** 编进
桌面测试（`tools/fw_test/stub/` 提供最小的 FreeRTOS / ESP-IDF 类型），
逐拍调用 `motion_tick()` 跑状态机，**36 项断言全过**：

| 场景 | 结果 |
|---|---|
| 趴 → 走三段时序 | 回站姿计时结束后是「站姿停留中」，不是直接走 |
| 停留期间输出 | 与站姿几何最大偏差 **0.0000°**、四脚最大前后位移 **0.0000mm** |
| 时间未到 | 目标动作仍被挂起，不提前放行 |
| 舵机滞后 60° | 100ms 时间到了仍不放行，等输出收敛并连续稳定后才走 |
| guard | 第 55 拍（1100ms）强制放行，不卡死 |
| 时长冻结 / 中途改目标 / 跑→走 / 已站稳直接出发 | 全部符合预期 |

`test_transition.c`（15 项）、`test_gait.c`、`test_pose.c` 三套旧单测回归全过。
固件 `spider8.bin` **954,832 B**，零编译告警，3MB 槽剩 70%。
