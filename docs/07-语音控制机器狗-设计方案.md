## 1. 总体架构

```
             ┌────────────────────────── ESP32-S3（全离线）──────────────────────────┐
             │                                                                      │
 INMP441 ──► │ I2S采集 ──► AFE声学前端 ──► WakeNet唤醒 ──┐                           │
 (麦克风)    │            (降噪/VAD)      "小八小八"     │ 唤醒音效                   │
             │                                          ▼                          │
             │                     ┌────────► MultiNet 命令词识别 ────┐               │
             │                     │        (确定性·快·稳)  命中│ 未命中          │
             │                     │                              ▼               │
             │                     │                   LLM 兜底理解                │
             │                     │                   (cmd-dog.pt)                │
             │                     │                              │                │
             │                     ▼                              ▼                │
             │              ┌──────────────────────────────────────┐              │
             │              │  动作校验层（门卫·按名字/按值拒绝）      │              │
             │              │  动作名存在？ 参数在安全范围？ 状态允许？ │              │
             │              └───────────────┬──────────────────────┘              │
             │                              │ 合法 ActionCmd（队列）               │
             │                              ▼                                     │
             │  BLE小程序 ◄─仲裁─► 命令总线 ──► 步态引擎/动作库 ──► LEDC 8路舵机      │
             │  (遥控/日志)        │              │                                │
             │                     │              └──► 超声波避障 / MPU6050 姿态    │
             └─────────────────────┴──────────────────────────────────────────────┘
```

三层安全（继承 gpio-llm 结论）：

1. **唤醒门**：没有唤醒词，后面全部静默——防误触发。
2. **理解层**：MultiNet 先行（命中即执行，不会理解错）；LLM 只接手未命中句子，且**允许输出"不知道"**。
3. **校验层**：动作名查表、参数限幅、状态机放行检查——无论上游谁批的，越界一律拒绝。模型的任何幻觉到了这里都"动不了腿"。

## 2. 语音前端设计（ESP-SR）

| 组件 | 选型 | 说明 |
|---|---|---|
| 声学前端 | ESP-SR AFE（VC/VAD/NS） | I2S 16kHz 16bit 单声道输入 |
| 唤醒 | WakeNet9（免费词优先） | 需求确认后定词；模型放独立 flash 分区 |
| 命令词 | MultiNet7 中文 | 以拼音串定义命令词，初版 ≤ 60 条；识别结果即命令 ID，**不走模型** |
| 音频输出 | I2S TX → MAX98357A / 蜂鸣器 | 提示音 + 语音反馈 |

拾音策略（对应 FR-V6）：

- 状态 `IDLE`：只跑 AFE+WakeNet（CPU 占用低）。
- 唤醒后 `LISTENING`：8s 窗口内做命令识别；期间暂停行走。
- 命令执行 `ACTING`：暂停拾音（舵机噪声），执行完回 `IDLE`。
- **例外**：`ACTING` 状态下保留一条高优先级命令词"停"——用独立检测路径（关键词 spotting），保证任何时候喊停都停。

## 4. 动作符号语法与"单一事实源"

### 4.1 符号集（从 gpio-llm 的 19 符号机制迁移）

gpio-llm 的模型输出是符号序列（如 `<set> <pin> 4 <high> <end>`），本项目的"大脑层"机制不变，只换积木：

```
句式骨架：
  <cmd> <act> 动作名 <arg> 数值 <end>
示例：
  "往前走五秒"        → <cmd> <act> walk <dir> forward <dur> 5 <unit> s <end>
  "坐一下"            → <cmd> <act> sit <end>
  "关掉闪灯"          → <cmd> <act> light <state> off <end>     （跨域样例）
  "今天天气怎么样"     → <unk> <end>                              （拒绝也是输出类）
```

- 动作名是**开放词表**：模型可以照抄出"翻跟头"这种动作表中不存在的名字 → 由校验层**按名字拒绝**（gpio-llm 血泪教训：把非法值做成"不可表示"，模型只会悄悄换成相近的合法值）。
- 数值逐位输出（`<dur> 3 0 <unit> s`），让校验层有东西可拒。

### 4.2 单一事实源

`action_symbols.json`（新文件，唯一动作表）派生出三份产物，杜绝 R6 的"两套理解"：

| 派生物 | 生成方式 | 消费方 |
|---|---|---|
| 符号头文件 `symbols.h` | 脚本 `gen_assets.py`（复用） | 固件解析器 + 校验层 |
| MultiNet 命令词表 | 脚本导出拼音串 | ESP-SR 初始化 |
| 训练语料 | `data/build_corpus_dog.py` 读取动作表生成 | 训练 + 评测 |

动作表初版（动作名 / 参数范围）：

| 动作 | 参数 | 范围（校验层限幅） |
|---|---|---|
| walk / turn | dir, speed, dur | dir ∈ {forward,back,left,right}；speed ∈ {1,2,3}；dur ≤ 30s |
| stop | — | 无参数，最高优先级 |
| sit / lie / stand | — | 静态姿态 |
| shake / greet / dance | — | 组合动作（依赖 M5 动作库） |
| light | state | on/off |
| battery | — | 查询类 |

## 5. 资源预算

| 资源 | 占用估算 | 余量说明 |
|---|---|---|
| Flash 总 16MB | app ~3MB + ESP-SR 模型 ~2.5MB + LLM 权重 1.2MB + 字体/资源 | 余量 > 60%，达标 NFR-V6 |
| PSRAM 8MB | AFE 缓冲 + MultiNet7 + LLM KV cache 302KB | 充裕 |
| **内部 SRAM ~512KB（最紧）** | ESP-SR AFE/WakeNet + BLE host + 8 路 LEDC + FreeRTOS 各任务栈 | **V0 里程碑必须实测 heap 峰值**，超限则 BLE 语音期分时复用 |

LLM 推理实测参考：gpio-llm 在同型号板上 150ms~1.5s/条，PSRAM 中跑 KV cache 无压力。

## 6. FreeRTOS 任务架构（固件纪律：静态分配、错误路径、不阻塞等待）

| 任务 | 优先级 | 栈（初值，以 high-water-mark 实测校准） | 核心 | 职责与通信 |
|---|---|---|---|---|
| audio_task | 6（最高） | 4 KB | 1 | I2S DMA 采集 → 环形缓冲；喂给 esp-sr；**ISR 中只做搬运** |
| sr_task | 5 | 8 KB（esp-sr 建议值） | 0 | AFE→WakeNet→MultiNet；命中经 `cmd_queue` 下发 |
| llm_task | 4 | 8 KB | 1 | LLM 前向推理（仅 LISTENING 且 MultiNet 未命中时唤醒） |
| motion_task | 5 | 4 KB | 1 | 步态引擎/动作库；只从 `cmd_queue` 收 `ActionCmd` |
| monitor_task | 2 | 2 KB | 0 | 电量/姿态/看门狗；紧急停车走 event group |

关键数据结构（校验层与动作层之间的唯一接口，288 字节量级、纯值传递）：

```c
typedef enum { ACT_WALK, ACT_TURN, ACT_STOP, ACT_SIT, /* ... */ } act_kind_t;

typedef struct {
    act_kind_t kind;        // 来自动作表，越界即拒绝
    int8_t     dir;         // -1 后/左，+1 前/右
    uint8_t    speed;       // 1..3，校验层限幅
    uint16_t   dur_ms;      // ≤ 30000，校验层限幅
    uint8_t    source;      // VOICE / BLE / AUTO —— 仲裁用
} action_cmd_t;
// 通道：xQueueSend/Receive（10 深度），STOP 用 event group 位直通，不走排队
```

仲裁规则（FR-V5）：`cmd_queue` 中同刻多源命令 → 最新生效；`ACT_STOP` 走 event group 直通位，任何任务任何状态立即清空队列、冻结 PWM。

## 7. LLM 迁移与训练计划（复用 gpio_llm 管线）

### 7.1 直接复用的资产

| 资产 | 复用方式 |
|---|---|
| 模型结构与参数量（312K） | 原样不动（"大脑层"不动，只换"耳朵层"——已验证的方法论） |
| 训练/导出脚本 `train.py`/`export.py` | 改语料路径即可 |
| 三道门禁 `tok_check.py`/`c_check.py`/`verify.c` | 原样重跑，门禁标准不变 |
| 设备端 UTF-8 分词器（已修） | 原样带入——这是中文版踩坑换来的，绝不能回退 |
| 符号机制与硬件校验思想 | 如 §4，扩符号表 |

### 7.2 需要新做的语料工程

1. `data/build_corpus_dog.py`：以 `action_symbols.json` 为骨架生成 15~20 万行中文语料（70% 正样本 / 30% 负样本）。
2. **中文语序模板必须前置内置**（第一轮训练的教训）：副词前置（"一直走""快一点走"）、"每秒五次地""翻个面"式口语、双分句"向前走三步，然后坐下"。
3. 负样本覆盖：闲聊、域外任务、做不到的动作（"翻跟头""跳起来"）、时间条件（"天黑以后再走"）、关于本机的问题。
4. **保留集纪律**：另写 ≥150 行全新手写评测集（写评测的人不看语料生成器——gpio-llm 反复强调"把考卷当练习册"的坑）。旧 102 行集合只做回归参考，不计入验收。

### 7.3 训练与验收门禁

| 门禁 | 标准 | 不过怎么办 |
|---|---|---|
| 门禁1 分词对拍 | 3000/3000 一致 | 修设备端 tokenizer |
| 门禁2 C 链路对拍 | 102/102（新保留集抽样）一致 | 查导出/采样路径 |
| 门禁3 前向数值 | 与 PyTorch golden logits 误差 < 1e-4 | 查量化/权重导出 |
| 门禁4（新）保留集评测 | 域内 ≥85%，误接受 ≤5%，**动了腿的误动作 ≤2%** | 回语料补覆盖，**不上板** |
| 门禁5（新）端到端语音实测 | 50 条口测：动作正确 ≥ 90%，危险输入 0 执行 | 修命令词表/语料，迭代 |

训练成本参考：语料 1 分钟 + 分词 3 分钟 + 训练约 72 分钟（CPU）+ 评测 2 分钟，一轮一晚绰绰有余；所有产物落 `E:\gpio_llm`（R5 约束）。

### 7.4 部署

`export.py` → 1.2MB 权重 bin → 独立 flash 分区原地映射读取；`sync.sh` 同步共享源进固件工程；编译烧写沿用 `tools/idf.ps1` 唯一入口（COM7，注意插 `USB` 口）。

## 8. 测试计划

| 层 | 测试项 | 方法 |
|---|---|---|
| 训练 | 门禁 1~4 | 自动化脚本，每次重训必跑 |
| 固件单元 | 校验层穷举：非法动作名/超范围参数/状态机拒绝 | host 端 C 测试（`host_verify` 扩展） |
| 语音链路 | 误唤醒率、噪声下识别率（舵机全转 vs 静止）、唤醒→动作延迟 | 计口测试脚本 + 串口日志时间戳 |
| 整机 | 72h 联调：栈水位（`uxTaskGetStackHighWaterMark`）、heap 峰值、看门狗复位恢复 | 串口日志 + 故障注入（低电压、BLE 断连中喊停） |
| 安全 | 危险指令注入（"以最快速度冲30秒""翻跟头"） | 预期全部拒绝且反馈；0 执行 |

## 9. 里程碑验收清单（与需求文档 §6 对应）

- **V0**：麦克风上板；PC 端录到干净波形；引脚表定稿；heap 峰值实测报告（决定 R2 走向）。
- **V1**：喊唤醒词→说"前进/后退/停"→单舵机点动正确；串口打印识别 JSON 与延迟。
- **V2**：模型过门禁 1~4；训练曲线与评测报告入库（`E:\gpio_llm\esp32-gpio-llm\runs\`）。
- **V3**：MultiNet 未命中的口语句子由 LLM 正确解析或拒绝；`<unk>` 路径实测；解析日志在 BLE 端可见。
- **V4**：语音控制完整步态；急停实测（运动中喊"停" ≤ 300ms 冻结）；误触发/安全注入测试全过；出具联调报告。
