## 0. 一句话说明

以前机器狗只认一根 USB 线：命令从电脑进去、回显从这根线出来，测试时人得一直守在电脑旁边。
现在有两条无线通道：**机器狗连你家路由器**（电脑照常上网，推荐），或者**机器狗自己发热点**（没路由时兜底）。两种都用同一个网页控制台，发的命令和串口**一模一样**。

把它想成「把对讲机的线剪掉，换成无线电」：**命令内容一个字没变**，只是送信方式换了。

> ⚠ **最后一次烧写仍然要插 USB 线**。烧完拔线，之后就再也不用连电脑了。
> 但拔线后 **ESP32 板子必须自己有电**（电池 / 充电宝 / 独立 5V），这一点软件帮不上忙。
> 配网一次即可：连上家里路由后热点自动关闭，断网自动重开。

## 1. 为什么不直接上蓝牙小程序

项目原计划 M3 接 BLE 微信小程序（`docs/01` D2、`docs/02` §7.1）。本模块**不推翻也不替代**它，两者定位不同：

| | 无线测试台（本次） | BLE 小程序（M3） |
|---|---|---|
| 用途 | 测试期调试：发任意命令、看 `status`、看系统日志、改参数 | 最终用户遥控：摇杆 + 几个动作按钮 |
| 终端 | 任何带浏览器的设备（Windows / Android / iPhone 通吃） | 微信小程序，需开发者工具 + 账号 + 真机调试 |
| 协议 | HTTP（纯文本命令，和串口一一对应） | BLE NUS 二进制帧 |
| 网页支持 | 原生 | iOS Safari 不支持 Web Bluetooth，只能走小程序 |
| 共存 | 可以 | 可以，两条入口最终都汇到同一张命令表 |

所以现在先解决「别拴着线」，M3 再解决「给外人用」。命令桥接层已经把入口抽象好了，M3 加 BLE 时不用动 `motion` / `gait` / `servo`。

## 2. 系统结构

```
  有线（保留兜底）                          无线（本次新增）
  电脑串口 ──USB Serial/JTAG──┐        手机/电脑浏览器 ──Wi-Fi 热点──┐
                              │        http://192.168.4.1           │
                              ▼                                     ▼
                      esp_console REPL                     httpd /api/cmd
                              │                                     │
                              └──────────► cli_exec() ◄────────────┘
                                     （共用执行锁 + 命令表）
                                              │
                              esp_console_run() ─► console.c 的命令函数
                                              │
                         motion ─► gait ─► servo ─► PCA9685 ─► 8 路舵机

  cli_out() 把每次输出同时送到三处：
    ① 有线 stdout（原行为不变）  ② 当前无线请求的回显  ③ 环形日志（/api/log）
  ESP_LOG 系统日志也接管进 ③，等于附送一个「无线串口监视器」。
```

**分层没被破坏**：`console` 仍然只改状态，不碰硬件；`motion` 仍是唯一决定关节角的地方；`servo` 仍是唯一写 PWM 的地方。

## 3. 交付清单

| 文件 | 作用 |
|---|---|
| `firmware/main/cli_out.h/.c` | 命令输出桥接：有线回显 / 无线捕获 / 环形日志，带执行锁 |
| `firmware/main/wireless.h/.c` | SoftAP + HTTP 接口 + 极简 DNS 强制门户 + 断连急停看门狗 |
| `firmware/main/web/console.html` | 手机 / 电脑自适应控制台网页，**构建时嵌进固件**，离线可用 |
| `firmware/main/console.c` | 61 处 `printf` → `cli_out`；REPL 失败时仍注册命令表 |
| `firmware/main/main.c` | 最早初始化 `cli_out`，`console_init()` 后启动无线 |
| `firmware/main/CMakeLists.txt` | 新增源文件、组件依赖、`EMBED_FILES` |
| `firmware/main/Kconfig.projbuild` | 新增「Spider8 无线测试台」菜单（开关 / SSID / 密码 / 信道） |
| `firmware/sdkconfig.defaults` | 默认启用无线测试台 |
| `console.c` 的 `wifidiag` 命令 | 有线诊断：热点搜不到时一条命令定位是哪一侧的问题（详见 §9） |
| `tools/wifi_spider8_profile.xml` | Windows WiFi 配置文件，解决「连着家里 5GHz 路由看不到 2.4G 热点」，可一键切换 |

**默认配置**：SSID `spider8`，密码 `spider888`（WPA2），信道 1，最多 4 台设备，网关 `192.168.4.1`。
改法：`idf.py menuconfig` →「Spider8 无线测试台」，或直接编辑 `Kconfig.projbuild` 的 default 后重新生成配置。

## 4. 使用步骤

### 4.1 烧写（只此一次还需要 USB 线）

```powershell
# 在工程目录 firmware/ 下执行；COM 号不固定，不要写死，让 esptool 自动探测
.\..\tools\idf.ps1 build
.\..\tools\idf.ps1 flash
```

**烧写前两件事**：

1. **先关掉占用串口的程序**——浏览器里开着的 `tools/servo_calib.html`（Web Serial）、`idf.py monitor`、其它串口工具，都会让 esptool 报
   `COM7 failed to connect ... PermissionError(13, 拒绝访问)`。本次第一遍烧写就是这么挡住的，关掉再烧即可，不要反复重试。
2. **先把四条腿悬空**（垫块或提起来）。固件上电会直接 `servo_init(站姿)`，腿着地时突然回站姿容易磕到齿轮。

若烧写后打开串口报「错误码 31 / 设备没有发挥作用」→ **物理插拔 USB**（软重启 PnP 无效，这是老坑，见 `docs/05`）。
烧写只写 app / bootloader / 分区表 / otadata，**不擦 NVS**，已经标定好并换算过的 8 条 trim 不会丢。

### 4.2 上电

拔掉电脑线，给机器狗供电：

- **ESP32 板子**：USB 口接充电宝 / 电池 5V；
- **8 路舵机**：`docs/11` 那套独立 5V 电源，别从 ESP32 板载取电；
- **三方共地**必须保留。

开机后看有线的启动日志（第一次可以留着线抓一下），会看到两种之一：

```text
# 已配过网、成功连上家里路由
I (wireless): NVS 读到家里 WiFi 配置: [TP-LINK_4440]
I (wireless): 正在连接家里 WiFi [TP-LINK_4440]
I (wireless): 已连上家里路由器，电脑照常上网；控制台 http://192.168.0.102
I (wireless): 已连上家里路由，热点 spider8 自动关闭（断网会自动重开）

# 没配网 / 路由连不上 → 退回热点兜底
I (wireless): 未配置家里 WiFi，仅启动热点（网页里可随时配网）
I (wireless): 热点 spider8 已启动，控制台 http://192.168.4.1
I (wireless): 无线测试台就绪；有线 USB 串口仍然可用
```

### 4.3 连热点

电脑 / 手机的 Wi-Fi 列表里找 `spider8`，密码 `spider888`。
连上后系统可能提示「无互联网连接」——**这是正常的**，这个热点只用于连机器狗，不需要外网，忽略即可。
手机上建议顺手关掉移动数据，避免系统自作主张切回蜂窝导致网页打不开。

> **⚠ Windows 电脑最常见的坑（2026-11-12 实测）**
> 电脑若正连着家里的 **5GHz WiFi**，Windows 的可用网络列表往往只显示当前那一个，
> 不会把 2.4GHz 的 `spider8` 刷出来 —— 此时热点其实是好的（实测信号 **99%**）。
> 三种解法任选其一：
>
> 1. **手动断开家里 WiFi**（点任务栏 WiFi → 当前网络 → 断开），等两秒刷新列表，`spider8` 就会出现，点它输入 `spider888`。
> 2. **不想反复输密码**：先导入一次配置文件，之后一条命令切换（本机 11-12 验收时已导入）：
>    ```powershell
>    netsh wlan add profile filename="tools\wifi_spider8_profile.xml" user=current
>    netsh wlan connect name="spider8" ssid="spider8" interface="WLAN"   # 切到机器狗
>    netsh wlan connect name="TP-LINK_4440" interface="WLAN"              # 切回家里（换成你的网络名）
>    ```
> 3. 手机测试时通常不受影响（没连 5G 路由时能正常搜到）。
>
> 判断是哪一侧的问题：插回 USB 线敲 `wifidiag`。若显示 `Wi-Fi 模式: ESP_OK, mode=2`
> + `SSID=[spider8]` + `HTTP服务=已启动`，说明板子完全正常，按上面第 1 步处理即可。

### 4.4 打开控制台

浏览器访问 `http://192.168.4.1`。网页存在固件里，**不需要联网、不需要拷贝任何文件**。
Android / iPhone 连上热点后通常会自动弹出「需要登录网络」页面，点进去就是控制台（固件里做了 DNS 应答器 + 404→303 强制门户）。

另外两种打开方式：

- **电脑本地双击** `firmware/main/web/console.html`：在页面「设置」里确认地址为 `http://192.168.4.1`。好处是改网页不用重烧固件；若浏览器拦了 file:// 的跨源请求，就改用上面那个地址。
- **以后连家里路由器**：目前没做 STA 模式，暂不支持；需要的话再加一个配网页面。

### 4.5 配网：让机器狗连家里路由（推荐，一次设置长期有效）

连机器狗热点时电脑不能上网。解法是**让机器狗反过来连你家路由器**，电脑/手机继续连家里 WiFi 照常上网，再通过家里网段的地址访问控制台。

两种写入方式，效果一样（都存 NVS、都会重启一次、都不动舵机 trim）：

**方式 A：网页里填（有热点时最简单）**

1. 连 `spider8` 热点 → 打开 `http://192.168.4.1`
2. 展开右下「网络 / 配网」→ 填家里 WiFi 名与密码 → 保存
3. 板子重启约 5 秒。若成功，**热点会自动关闭**，面板会显示「控制台地址 `http://<家里网段IP>`」

**方式 B：串口直接写（网页配网报 `Failed to fetch` 时用这条）**

```text
wifiset TP-LINK_4440 你的密码
```

- 密码含空格用引号包住；开放网络写 `wifiset <ssid> -`
- 写入后 1.5 秒自动重启
- 查结果：`wifidiag` → 应显示 `配网=已配置`、`STA已拿到IP=是`、`STA 地址=192.168.x.x`
- 想撤销：`wificlear` → 重启回到纯热点

**热点行为（11-12 起）**

| 状态 | 热点 | 说明 |
|---|---|---|
| 已连上家里路由 | **自动关闭** | 列表里看不到 `spider8` 属正常，省电、不占 2.4G |
| 路由断开 / 密码错 | **自动重开** | 从 `192.168.4.1` 进来重填，不会失联 |
| 从没配过网 | 一直开着 | 纯热点模式，和以前一样 |

**连上之后怎么找地址**：`wifidiag` 会打印（本次实测 `192.168.0.102`，路由器可能改）。也可试 `http://spider8` —— 固件把 DHCP 主机名设成了 `spider8`，很多路由器支持按名解析。

### 4.6 舵机标定台也能走 WiFi（2026-11-13）

`tools/servo_calib.html` 以前只能用 Web Serial 连 USB 线，现在和控制台一样支持 **WiFi 优先 + USB 兜底**，打开就能用：

| | WiFi（默认） | USB 串口（兜底） |
|---|---|---|
| 怎么连 | 页面打开自动寻找机器狗，或点 ①「🌐 WiFi 连接」 | 点 ①「🔌 改用 USB 串口」，弹窗里选 VID 303A 的口 |
| 命令走哪 | `GET /api/cmd?c=<命令>` | 往 REPL 写一行 CRLF |
| 浏览器要求 | 任意支持 fetch 的浏览器 | 必须 Edge / Chrome（Web Serial） |
| 什么时候用 | 平时标定、调 trim、读状态 | 没配网 / WiFi 断了 / 要烧写时 |

**关键点**：两条通道的命令都进固件同一张命令表，`cli_exec()` 捕获的 `status` 表格与串口回显**逐字相同**，所以标定台原有的 8 路 trim/dir 解析、⑤ 换算快照、`dir` 安全翻转防覆盖逻辑一行都没改。连上 WiFi 会自动发一次 `status`，把板子里 NVS 的 8 路 trim/dir 读回来。

**自动寻址**：候选顺序是「网址里带的 `?api=` → 上次配网成功地址 `spider8.sta` → 手填过的 `spider8.api` → `192.168.0.102` → `192.168.4.1`」，**只认真正回 `pong` 的那个**。页面顶部黄框会显示找到的地址，并给一个「打开板子里的网页控制台」新窗口按钮。`/api/net` 每 4 秒把板子当前地址写回 `spider8.sta`。心跳 800ms，只认 `pong`，连续 3 次失败才把按钮灰掉。

**11-13 下午修复「console.html 能连、标定台连不上」**：真因有两条叠加——

1. **`localStorage` 是按「打开方式（源）」隔离的**。`console.html` 通常是从板子内嵌页 `http://<板子IP>/` 打开的，走**同源直连**（`apiBase=''`，压根不需要找地址）；它写下的 `spider8.sta` 存在那个源下，双击本地 `file://` 打开的标定台**读不到**，两边并不共享记录。
2. **候选表里只有 4 个写死地址**，而板子 IP 由路由器 DHCP 分配会变。IP 一变，标定台就再也找不到，而控制台照样能连 → 看上去像"标定台坏了"。

现在固定候选全部落空后，会**按网段批量扫描**（优先扫「记住的地址所在网段」，因为 DHCP 换 IP 通常只换最后一段；再扫 `192.168.0/1/4`），每批 64 个、`600ms` 短超时，找到第一个真回 `pong` 的地址立刻连上并记住。另外支持在网址后直接加 `?api=http://板子IP` 指定地址。手动填地址或点「改用 USB 串口」会 `stopProbe()` 让后台扫描立即作废，不会顶掉用户的选择。

⚠ 电脑开着 VPN（本机实测 LetsTUN 把主 IP 变成 `26.26.27.1`）时，扫描请求会被送进隧道，一个 `pong` 都收不到——这时**先退 VPN**，别再挨个换地址试。

**两条沿用控制台的防线**：① `192.168.4.1` 只排候选最后，连上家里路由后热点已关闭，那个地址常是别的设备 / VPN 带过去的交换机登录页（识别到 `Web user login` 会直接提示「不是机器狗，别输密码」）；② 从 `https://` 页面访问 `http://` 板子会被浏览器混合内容拦截，用本地文件或板子自己的网页。

**烧写时**：WiFi 通道不占串口，但**烧写仍需 USB 独占**——如果标定台用着 USB，先点「断开」；用 WiFi 则不必。

**一个坑：`http://` 打开 ≠ 打开的是板子。** 也可能是本地静态服务、编辑器预览面板（例如 `127.0.0.1:8571`）。所以页面先探**同源** `/api/ping`，只有真回 `pong` 才把 `apiBase` 留空做同源直连并隐藏地址条；否则照样走候选自动寻址，不会把预览服务器的 404 当成机器狗。

**验证记录（11-13）**：

- 静态：`node --check` 通过；85 个 id 无重复、83 个 JS 引用全部存在、43 个函数无重复定义；用真实串口 `status` 日志复刻表格行正则，8 行全中（负号是 ASCII `-`，不是 U+2212）。
- 无头 Edge 四种打开方式全过：① 板子内嵌网页（http 同源）；② 预览面板（http 非板子，localStorage 记住过地址）；③ 预览面板（http 非板子，无任何记录）；④ 双击本地文件（`file://`）。都显示「已连接 · WiFi」、`status` 解析出 8 路 trim、⑤ 保存等按钮全解锁。
- **真板上板实测**（测试期间板子通电后补做）：无预置地址的 `file://` 页面自动找到 `http://192.168.0.102`（`/api/net` 报 STA `TP-LINK_4440`、RSSI −50），读回的 8 路 trim 与 `curl /api/cmd?c=status` 逐位一致，按钮全解锁。全程只发只读 `status` 与心跳 `ping`，**没写 NVS、没驱动舵机**。
- **11-13 下午补测（网段扫描修复）**：本地起模拟 API 服务，无头 Edge 两种路径都过——① 网址带 `?api=http://127.0.0.1:18768` 直接连，显示「已连接 · WiFi」、8 路 trim 全解析、⑤ 保存按钮解锁；② 故意把 `spider8.sta` 预置成失效地址，页面自动走网段扫描找到新地址并连上，同样读回 8 路 trim。`status` 里新增的「动作切换 …」行没有干扰表格解析。静态检查：1 个 script 块、85 个 id 无重复、45 个函数无重复、`node --check` 通过。**真机扫描路径待板子在线 / VPN 退出后复验。**

## 5. 界面能做什么

| 区块 | 说明 |
|---|---|
| **急停**（最上方大红按钮） | 直接调 `/api/stop` → `motion_stand()`，**不走命令排队**，哪怕 `pwmscan` 正跑 19 秒也能立刻停 |
| 实时状态 | 每 1.5 秒刷新：模式 / 姿态 / 峰值角速度 / 软限位次数 / 空闲内存 / 连入设备 / 心跳 / 运行时长；`/api/status` 的 `trans` 字段显示「回站姿中 / **站姿停留中** / 起步淡入中」，`hold` 字段是站姿停留时长（默认 300ms，命令 `standhold` 可调，见 docs/13 §4.9） |
| 动作 | 站立、蹲下、趴下、握手、挥手、连续演示 |
| 行走 / 转向 | 波步前进 `walk 100`、小跑 `trot 100`、停止；**原地左转 `left` / 右转 `right` / 回正直行 `straight`**；速度 / 转向滑块（松手才发命令） |
| 高级参数 | 周期 / 步幅 / 抬脚 / 占空比滑块 |
| 命令终端 | 任意串口命令 + 回显，回车即发；`status` / `pcadiag` / `pwm off` / `cal off` 快捷键 |
| 系统日志 | 折叠开关，展开后每 0.8 秒拉一次 ESP_LOG，等于无线串口监视器 |
| 命令速查 / 设置 | 全部命令表、两条安全线、连不上时的排查顺序 |

**命令与有线串口完全一致**，没有另造一套协议。例如网页点「波步前进」和串口敲 `walk 100` 走的是同一个 `cmd_walk()`。

## 6. HTTP 接口（给以后扩展用）

| 接口 | 方法 | 说明 |
|---|---|---|
| `/` | GET | 内嵌网页 |
| `/api/cmd?c=<命令>` | GET | 执行一行命令，返回纯文本回显；命令出错返回 400 但正文仍是回显 |
| `/api/stop` | GET | 急停，绕过命令执行锁 |
| `/api/ping` | GET | 心跳，网页每 500ms 一次 |
| `/api/status` | GET | 结构化状态 JSON（给状态面板） |
| `/api/log?since=<字节序号>` | GET | 环形日志增量；`X-Log-Now` 响应头给出新的序号 |
| 其它路径 | GET | 303 跳到 `/`（配合 DNS 应答器实现强制门户） |

所有 `/api/*` 都带 `Access-Control-Allow-Origin: *`，所以本地 html 文件直开也能访问。
命令参数用 `encodeURIComponent` 编码，固件侧会还原百分号转义（`httpd_query_key_value` 本身不解码，已自己补上）。

## 7. 安全机制（测试期很重要）

1. **断连自动停车**：网页每 500ms 发心跳。心跳断超过 **2.5 秒**且当前处于 `MODE_WALK`，固件自动 `motion_stand()`，避免关掉网页 / 手机切后台 / 走出 Wi-Fi 范围后机器狗一直往前跑撞墙。看门狗只触发一次，之后有线操作不会被误伤。
2. **急停特权通道**：不等命令锁、不排队。
3. **命令执行锁**：多个网页同时发命令时串行执行；`demo` / `pwmscan` 这类长命令会让后续命令排队（网页终端会显示「排队」），最多等 30 秒。
4. **捕获按任务归属**：用 `xTaskGetCurrentTaskHandle()` 判断输出属于哪次无线执行，有线 REPL 与 HTTP 并发时回显不会串台。
5. **无线启动失败不致命**：`wireless_init()` 返回错误只打日志，运动功能和有线串口照常工作。

### 两条沿用自标定阶段的安全线

- 腿已装好时 **禁止 `pwmscan all`**：全行程约 19 秒，会把腿甩到硬限位。
- 改 `dir` 之前必须 `pwm off` → `cal off` → `pose stand` → 等 ≥600ms。站姿时差值为 0 翻转 dir 不动，但正在点动 / 行走时翻转会把腿镜像过去猛转（`docs/13`）。网页里没放 `dir` 快捷按钮，只在速查表里写了安全序列。

## 8. 供电检查（务必做）

Wi-Fi 发射瞬间会额外拉 **约 0.3A 峰值电流**。本项目刚踩过「电池盒空载 5V 漂亮、舵机一启动就塌压 → 8 只舵机全不动」的坑（`docs/11` §6.12 与最终结论）。加无线之后这条风险只会更大。

**验证方法**：发 `walk 100` 或 `pwm 0 2500` 的瞬间，用万用表量舵机红线对地电压。

| 现象 | 判断 | 处理 |
|---|---|---|
| 5V 稳得住 | 电源够 | 继续测 |
| 掉到 4.5V 以下 / 板子重启 / 热点消失 | 带载不足 | 换更大电流的电源、或给 ESP32 单独供电，别去改固件 |

状态面板里的「空闲内存 / 最低内存」也能顺带看一眼：Wi-Fi + lwIP + httpd 会多占几十 KB 内部 RAM，若 `heap_min` 明显偏低要到 `menuconfig` 里关掉无线或减小 httpd 连接数。

## 9. 排错表

| 现象 | 原因 / 处理 |
|---|---|
| **Wi-Fi 列表里没有 `spider8`（最常见）** | **先别怀疑固件**：插 USB 敲 `wifidiag`。若显示 `mode=2` / `SSID=[spider8]` / `HTTP服务=已启动`，说明热点正常在跑，只是 Windows 连着家里 5GHz 路由时列表不刷 2.4G 热点 → 断开当前 WiFi 再刷新，或用 `netsh wlan connect name="spider8" ssid="spider8" interface="WLAN"` 直接切（§4.3）。只有 `wifidiag` 报 `ESP_ERR_WIFI_NOT_INIT` / 网口不存在时，才去看启动日志、供电和 `Kconfig.projbuild` |
| 想知道板子到底起没起无线 | 有线串口敲 `wifidiag`：一次输出 Wi-Fi 模式、SSID/信道/认证、已连设备数、AP IP、HTTP 状态，并附开机以来的系统日志（16KB 环形缓冲，**不用抓启动瞬间**） |
| 连上热点但网页打不开 | 确认地址是 `http://192.168.4.1`（不是 https）；关掉手机移动数据；电脑若同时连着别的网，暂时断开其它网卡再试；忽略「无互联网」提示 |
| 一直提示「连不上」 | 用有线串口看 `I (wireless):` 日志；确认 httpd 启动成功；确认 5V 没掉压 |
| 点命令没回显 | 看终端区红色报错；`help` 命令由 esp_console 内部直接 printf，不走捕获，网页速查表已内置命令列表 |
| **右上角「已连接」但实时状态全是「—」（11-13 修）** | 先自检服务端：`curl http://<板子IP>/api/status` 应回 200 + JSON（实测正常）。当时是网页端三个坑叠加：① 旧版心跳只看「有响应」，404 / 强制门户 / 别的设备页面都会误显示「已连接」；② 状态读取失败被 `catch(){}` 静默吞掉，面板没有任何提示；③ `file://` 打开时 `localStorage` 可能记着已失效的热点地址 `192.168.4.1`（热点在连上路由后已自动关闭）。本版已改：心跳必须回 `pong` 才算连上、状态失败在卡片里显示红字原因（含目标地址与返回片段）、连续失败自动改用上次配网成功的地址、轮询降到 800/2000/4000ms。**改网页后必须重编烧录**（`EMBED_FILES` 嵌进固件），浏览器再 Ctrl+F5 强制刷新 |
| `/api/status` 轮询失败 | 浏览器控制台（F12）看 CORS 报错；内嵌网页是同源，正常不会有。新版会直接把 HTTP 状态 / 超时 / 非 JSON 片段写在状态卡片顶部 |
| 机器狗走两步自己停了 | 心跳断了（网页切后台 / 手机锁屏 / 走出范围）。这是**设计行为**，回来点一下页面重新武装即可 |
| 烧写后 USB 口打不开 | 老坑：物理插拔 USB，不要写死 COM 号 |
| 命令行 `help` 显示不全 | 有线串口用 `help`；无线侧请用网页「命令速查」 |
| **网页配网报 `Failed to fetch`（11-12 实测）** | 三层原因，按顺序查：① 本机 **VPN / 加速器（本机是 `LetsTUN`）会抢 `192.168.4.1` 的路由**，请求被送进隧道撞到别的设备（实测返回 H3C 404 页）→ 暂时退出 VPN 再试；② **Windows 连上 `spider8` 后几秒会自动切回家里 WiFi**（热点无互联网）→ `netsh wlan set profileparameter name="spider8" connectionmode=manual` 改成手动，连上后就不会被切走；③ 实在不行用串口 `wifiset <ssid> <pass>` 直接写（§4.5） |
| **打开 `192.168.4.1` 跳出要账号密码的登录页（11-13 实测）** | **那不是机器狗，别输密码**。实测响应头 `Server: Lanswitch - V100R003 HttpServer 1.1`、标题 `Web user login`（华为/H3C 交换机管理页）；`Find-NetRoute` 显示本机到 `192.168.4.1` 走 **LetsTUN VPN 虚拟网卡 26.26.27.1**，请求被送进隧道撞上别人的设备。根因：板子连上家里路由后热点按设计自动关闭，`192.168.4.1` 已不再属于机器狗。正确地址看 `/api/net` 的 `console` 字段（当时 `http://192.168.0.102`）。测试前退出 VPN；`http://spider8` / `spider8.local` 实测本机不解析（路由器不做本地主机名解析、固件未启用 mDNS），只能记 IP，建议在路由器里把 STA MAC `1C-29-04-24-BD-CC` 静态绑定成 `192.168.0.102`。网页已把误导文案改成醒目红字，并会识别登录页直接给出提示 |
| 配网写进去了但连不上路由 | `wifidiag` 看 `配网=已配置` + `重连次数`；注意日志里的 `ESP_ERR_WIFI_MODE` —— 那是固件早期 bug（set_config 在 set_mode 之前），本版已修。`wifiset` 重写一次最省事 |
| 开机就重启 / 日志里 `stack overflow in task sys_evt` | Wi-Fi 事件回调栈不够。本版已把 `CONFIG_ESP_SYSTEM_EVENT_TASK_STACK_SIZE` 从 2304 提到 **4608**；若自己改回调又加了大局部变量，继续上调 |
| 热点忽然从列表消失 | 若 `wifidiag` 显示 `mode=1` 且 `STA已拿到IP=是`，这是**设计行为**：连上家里路由后热点自动关闭。断电路由器或 `wificlear` 即可恢复 |
| **电脑和手机同时打不开板子里的网页（11-13 实测）** | 现象：`ping <板子IP>` 通（0% 丢包）、ARP MAC 是板子本人、TCP 80 能连上，但连续 30 次请求全部 `ConnectionResetError`、一个字节不回 —— **不是手机、网段或 VPN 的问题，是板子里的 httpd 线程卡死**（Wi-Fi / lwIP 还活着）。当时电脑「能看」的只是早先双击打开的本地 html 文件，不是板子内嵌页。临时恢复＝**把板子所有供电线拔掉 5 秒再插回**（只拔 USB 线不行，若还有独立 5V 电源等于没断电）。本版已加三层防护：① 所有响应带 `Connection: close`，不让浏览器复用连接占满会话槽；② `max_open_sockets` 7→9、`backlog_conn` 5→12（受 `CONFIG_LWIP_MAX_SOCKETS=10` 限制）、命令等锁 30s→2.5s 快速失败；③ 新增 `/api/guard` + `wd_http` 自愈任务，上电 30s 后每 5s 从板子内部自检，连续 8 次（约 40s，给 `pwmscan` 19s 留余量）无响应自动 `esp_restart()`。**不能用 `httpd_stop()` 自愈**——它会 `while (status != THREAD_STOPPED) sleep(100)`，httpd 卡死时自己也会卡住。重启不擦 NVS，配网与 trim 不丢，但舵机回默认站姿 → 上电前四脚悬空 |

## 10. 配置开关与 M3 衔接

- 完全关掉无线：`idf.py menuconfig` →「Spider8 无线测试台」→ 取消「启用 Wi-Fi 热点与网页控制台」。`wireless.c` 会退化成一个只打日志的空实现，Wi-Fi 相关代码仍编译但不启动。
- 想把热点改成免密码：勾选「开放热点」，但**附近任何人都能连上并让狗走路**，只建议隔离环境临时用。
- M3 加 BLE 时：在 `cli_exec()` 之外再包一层 `ble_exec()` 即可复用同一套命令与回显，或者在 `ble_task` 里直接调 `motion_*` 走二进制帧。两条入口互不干扰；若两者同时在线，建议按 `docs/07` 的命令仲裁规则加「最新指令生效 + 急停最高优先级」。

## 11. 已知限制

- 已支持 **STA 连家里路由**（连上后热点自动关闭）；没配网或路由失联时退回纯热点，两种情况都能控狗。
- 退出热点范围（且没连家里路由）会断开；心跳断 2.5 秒会自动停车。
- 热点是 2.4G，穿墙一般；测试建议在同房间。
- 家里路由分配的 IP **可能变**；变了用 `wifidiag` 查，或试 `http://spider8`（DHCP 主机名）。
- 网页是**明文 HTTP + 简单 WPA2**，只在本地测试用，不要暴露到公网。
- `help` 命令的输出不进无线回显（esp_console 内部实现），已用网页内置速查表覆盖。
- 同时开多个网页标签都会发心跳，关掉其中一个不会触发停车（另一个还在 ping）。
