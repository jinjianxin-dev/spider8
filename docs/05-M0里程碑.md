## M0-1 过程中修复的环境问题（速查）

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | IDF 激活用了系统 Python 3.14 | `export.ps1` 调 PATH 里的 `python` | `idf.ps1` 硬绑定 `IDF_PYTHON_ENV_PATH` + venv PATH 前置 |
| 2 | `idf5.5_py3.14_env not found` → `. $idf_exports` 报"表达式无效" | 上条的连带后果（venv 目录名跟着 python 版本走） | 同 #1；详见 `docs/04` §4.1 |
| 3 | IDF 子模块缺失（micro-ecc / esp_coex 等） | **全局 git 配置把 github.com 改写到已停服的 `ghproxy.com`** | 构建时用 `GIT_CONFIG_GLOBAL=/dev/null` 绕过；建议全局清掉该规则 |
| 4 | Gitee 镜像缺部分子模块仓库 | 镜像同步不全 | 换用 GitHub 官方 `.gitmodules` + 8 路并行拉取 |
| 5 | 串口中文日志乱码 | 控制台代码页 936 vs 固件 UTF-8 | `idf.ps1` 在 monitor 时自动 `chcp 65001` |
| 6 | PS 脚本中文报"意外的标记 }" | PowerShell 5.1 需要 UTF-8 **BOM** | 所有 `.ps1` 统一 BOM + CRLF 保存 |
| 7 | VS Code 任务卡在"正在执行中"、且报 `py3.14_env not found` | 默认终端 profile（ESP-IDF Shell）带 `-NoExit`，VS Code 把任务命令行追加成它的参数吞掉了 | 任务改用 `options.shell` 显式指定干净 shell；终端改调 `tools/idf_shell.ps1`（详见 `docs/04` §4.2） |

## 下一步：M0-2 舵机驱动与校准框架

**目标**：8 路 LEDC PWM 输出 50Hz 标准舵机信号 + 中位校准 + 软限位保护。

**计划交付**：
1. `main/servo.c/.h`：8 通道 LEDC 驱动器
   - 50Hz（20ms 周期），脉宽 500~2500µs 可调，分辨率 14bit
   - 角度 → 脉宽线性映射，带每关节的 `min/max/center/trim` 校准参数
   - 堵转保护：指令突变时间窗限制（MG90S 无反馈，靠"斜率限制"防止瞬间大电流）
2. `main/config.h`：8 个关节的引脚 / 标定表（初值待实测填入）
3. 校准 CLI：串口输入 `cal <id> <angle>` 单关节点动，`save` 落 NVS
4. 自检动作：上电"起立 → 中位保持 → 趴下"

**硬件未到齐也能验收**：把 LED + 220Ω 电阻接在舵机信号脚上，50Hz PWM 下亮度随脉宽（1ms→2ms）明显变化，可肉眼确认 8 路输出正确。

**验收标准**：
- [ ] 8 路 PWM 全部输出 50Hz，示波器/LED 可验证
- [ ] 串口 `cal` 命令能单独驱动任一关节
- [ ] 校准参数掉电可保存（NVS）
- [ ] 舵机接线到货后，能完成"起立/趴下"自检动作
