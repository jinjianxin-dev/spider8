### 引脚（与 02 方案 §2.1 一致）

| 通道 | GPIO | 关节 | 通道 | GPIO | 关节 |
|---|---|---|---|---|---|
| CH0 | 4 | FL 髋 | CH4 | 15 | RL 髋 |
| CH1 | 5 | FL 膝 | CH5 | 16 | RL 膝 |
| CH2 | 6 | FR 髋 | CH6 | 17 | RR 髋 |
| CH3 | 7 | FR 膝 | CH7 | 18 | RR 膝 |

> ⚠ GPIO4 原来是 M0-1 的心跳 LED，现已让给舵机 CH0。心跳改为纯日志，不再占用引脚。
> 舵机电源必须**独立 5V 轨**，只共地 —— 8 个 MG90S 同时堵转能拉到 8A，直接灌进开发板的 5V 会掉压复位。

### 装配基准（最关键的一步）

**把四条腿摆成"站立姿态"，再把舵机臂装到 90°。**

站立姿态的几何是：膝屈 **-38°** → 髋角自动反解 **19°** → 髋轴离地 **104.0mm**。
驱动里 `90° = 站姿` 这个约定成立，后面所有动作（蹲下 95.3mm、趴下 74.3mm）才都能算对。

装不精确没关系，用 `cal` 点动 + `trim` 微调 + `save` 存 NVS。

如果某条腿方向装反了（关节角增大它却往反方向转），用 `dir <关节> -1` 翻过来，不要重新拆装。

### 串口命令

**连的是板上标 `USB` 的口**（原生 USB Serial/JTAG，免驱，VID 303A），不是 `UART` 口。
提示符是 `spider8>`。波特率写 115200 即可（USB CDC 下该参数不起实际作用）。

> ⚠ 若烧写后串口打不开、报"连到系统上的设备没有发挥作用"（错误码 31），
> 是本机 USB 驱动被固件复位动作卡住：**拔掉 USB 再插回**即可恢复，
> 且串口号可能变化（COM7 ↔ COM8），以设备管理器为准。

| 命令 | 说明 |
|---|---|
| `status` | 8 个关节的关节角/舵机角/dir/trim，姿态参数，峰值角速度与余量，堆栈余量 |
| `demo` | 自动演示：蹲下 → 站立 → 握手 → 挥手 → 站立（约 9 秒） |
| `pose stand\|crouch\|lie\|shake\|wave` | 切换姿态 |
| `walk [速度]` / `trot [速度]` | 波步 / 小跑，速度 0~100 |
| `stop` | 停止并站定 |
| `speed <0-100>` / `turn <-100..100>` | 速度 / 差速转向 |
| `period <800-3000>` / `stride <8-30>` / `lift <6-26>` / `duty <10-45>` | 步态参数在线调整 |
| `cal <0-7> <关节角>` | 单关节点动（旁路软限位） |
| `cal off` | 退出标定，回到站立 |
| `trim <0-7> <-50..50>` | 舵机微调角 |
| `dir <0-7> <1\|-1>` | 翻转舵机方向 |
| `save` | 标定值写 NVS |
| `pwm <0-7\|all> <500-3000>` | **电气验证**：固定脉宽输出（旁路全部姿态逻辑；上限 3000 供 360° 大行程舵机测端点） |
| `pwm off` | 退出脉宽测试，回到站姿 |
| `pwmscan <0-7\|all>` | **电气验证**：脉宽呼吸扫描，看 LED 由暗到亮 |

### 验收步骤（按硬件到位程度分三档）

**A. 舵机还没到 —— 用 LED 验证 PWM**

完整步骤见 **`08-LED与PWM验证.md`**（接线图、电阻选型、期望亮度、万用表读数、异常排查全在里面）。

三十秒版：

```
LED 长脚 → GPIO4      短脚 → 220Ω → GND
pwm 0 500    → 很暗
pwm 0 2500   → 明显变亮（约 5 倍）
pwmscan 0    → 呼吸两个来回
pwmscan all  → 8 个脚上的 LED 同步呼吸（每路串 470Ω 以上）
pwm off      → 回站姿
```

判定：`pwmscan 0..7` 逐个扫描时，**只有对应该 GPIO 的 LED 亮**，其余 7 个必须全黑。
这条能抓出短线和引脚表填错。

**A 档实测结果（2026-11-05）—— ✅ 通过**

单个红色 LED + 220Ω，信号线逐根挪到 8 个引脚上，每根用 `pwm <ch> 500 / 1500 / 2500`
三档对比亮度，8 路**全部逐级变亮**：

| 通道 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| GPIO | 4 | 5 | 6 | 7 | 15 | 16 | 17 | 18 |
| 结果 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |

结论：LEDC 定时器、8 个通道、引脚映射、占空比换算**全部正确**，
`servo.c` 的 `k_pin[]`（值来自 `config.h` 的 `SERVO_PIN_*`）与实物接线一致。
剩下的风险只在舵机本体和供电。

**B. 到一个舵机 —— 验证单关节**

接 CH0（GPIO4）。`cal 0 19` 应回到站姿角度；`cal 0 40` 应向前摆；`cal 0 0` 应竖直向下。

**C. 8 个舵机全接 —— 完整验收**

```
status        # 看 8 个通道角度是否合理，峰值角速度余量
pose lie      # 趴下（74.3mm）
pose stand    # 站起来（104.0mm）
demo          # 蹲→站→握手→挥手
walk 60       # 低速走 1~2 个周期，观察是否拖地
```

### 已知限制

1. **2-DOF 腿不能横向跨步**，转向只能靠左右差速（`turn` 命令）。
2. **握手/挥手不是真正的侧向递爪**，是"抬起 + 前伸"，方向朝前。要真侧向得加第三个关节。
3. **默认参数下峰值角速度 451°/s**，占 MG90S 的 75%。把周期压到 800ms 会到 ~680°/s 超限，`status` 会标红。
4. **没有 IMU、没有舵机位置反馈**，所有控制都是开环按时间推进。地面打滑、电池掉压都会让实际步幅变小，只能靠目视校正。
5. **`pwm` 是旁路命令**：它绕过软限位、trim、dir 和斜率限制，直接写脉宽。只用于电气验证，
   接上舵机后不要拿它当角度控制用（要动关节用 `cal`）。

### 本轮踩到的环境坑

| 问题 | 根因 | 处理 |
|---|---|---|
| `python : 无法将"python"项识别为…` | 会话里 `PATHEXT` 被改成了只剩 `.CPL`，PowerShell 不会去找 `.exe` | 运行前 `$env:PATHEXT = ".COM;.EXE;.BAT;.CMD;.VBS;.VBE;.JS;.JSE;.WSF;.WSH;.MSC"` |
| `ccache: could not find configuration file and the LOCALAPPDATA environment variable is not set` | 会话里 `LOCALAPPDATA` 为空 | 运行前 `$env:LOCALAPPDATA = "C:\Users\$env:USERNAME\AppData\Local"` |
| `Failed to resolve component 'esp_console'` | IDF 5.5 里组件名是 **`console`**，`esp_console` 只是头文件名 | `PRIV_REQUIRES ... console ...` |
| `esp_app_desc.h: No such file` | 显式写 `REQUIRES` 后不再继承公共依赖 | 把 `esp_app_format / esp_partition / spi_flash / esp_hw_support / heap` 全部列进 `PRIV_REQUIRES` |
