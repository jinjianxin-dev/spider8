## 1. 系统总体架构

### 1.1 当前形态（M0-2 已实现）

```
   USB Serial/JTAG (VID 303A)               ┌──────────────────────────┐
   电脑终端 ──────────────────────────────►  │  console_task  prio 3    │
   （`spider8>` 提示符）                     │  pose/walk/cal/pwm/...   │
                                           └───────────┬──────────────┘
                                                       │ 改模式、改参数
                                           ┌───────────▼──────────────┐
                                           │  motion_task  prio 5     │
                                           │  20ms 定拍               │
                                           │  ├ 步态引擎 gait.c       │
                                           │  ├ 静态位姿求解          │
                                           │  └ 斜率限制 550°/s       │
                                           └───────────┬──────────────┘
                                                       │ 队列(长度1，覆盖写)
                                                       │ 8 个关节角
                                           ┌───────────▼──────────────┐
                                           │  servo_out_task  prio 7  │
                                           │  20ms 定拍，唯一写 LEDC  │
                                           │  软限位 / 硬限位 / 12°拍 │
                                           └───────────┬──────────────┘
                                                       ▼
                                              8 路 PWM → 8×MG90S
```

**分层原则**：`console` 只改状态和参数，**不直接碰硬件**；`motion` 是唯一决定"关节该转到多少度"
的地方；`servo` 是唯一写 LEDC 的地方。这条界线保证了后面加 BLE 时，只需要再写一个"改状态"的入口，
运动层一行不用动。

### 1.2 目标形态（M3 之后追加）

```
  微信小程序 ──BLE NUS──► ble_task ─┐
                                    ├──► 模式仲裁（EventGroup）──► motion ──► servo
  HC-SR04 ──────────────► obstacle ─┘
```

三层解耦：**人机入口（串口/BLE）↔ 运动决策（motion）↔ 硬件驱动（servo）**。

## 2. 硬件设计

### 2.1 引脚分配（与 `main/config.h` 完全一致）

| 通道 | GPIO | 关节 | 通道 | GPIO | 关节 |
|---|---|---|---|---|---|
| CH0 | 4 | FL 髋 | CH4 | 15 | RL 髋 |
| CH1 | 5 | FL 膝 | CH5 | 16 | RL 膝 |
| CH2 | 6 | FR 髋 | CH6 | 17 | RR 髋 |
| CH3 | 7 | FR 膝 | CH7 | 18 | RR 膝 |

预留：

| 功能 | GPIO | 说明 |
|---|---|---|
| HC-SR04 TRIG | 38 | 推挽输出 10µs 触发 |
| HC-SR04 ECHO | 39 | **必须 1k/2k 分压**到 3.3V |
| 电池电压 ADC | 10 | ADC1_CH9，33k/10k 分压 |
| WS2812 眼睛 | 48 | RMT 驱动 |

> ⚠ GPIO4 原来是 M0-1 的心跳 LED，现已让给舵机 CH0；心跳改为纯日志输出，不再占引脚。
> 避开 strapping 引脚（0/3/45/46）与 UART0（43/44）。

### 2.2 电源架构

```
2S 18650 (7.4V, 带保护板)
 ├─► DC-DC 5V/5A ──┬─► 舵机轨（8×MG90S）
 │                 └─ 并联 2200µF 低 ESR 电容（吸收堵转尖峰）
 └─► 5V ──► AMS1117 3.3V ──► ESP32-S3 / HC-SR04
电池 ──► 33k/10k 分压 ──► GPIO10
```

**舵机轨与主控轨必须分开，只共地。** 8 个 MG90S 同时动作实测 2~3A，峰值按 5A 冗余；
直接灌进开发板的 5V 会掉压复位。低压阈值 3.4V/cell 报警趴下，3.3V/cell 强制停机。

### 2.3 乐高结构

- **乐高兼容舵机支架**（MG90S 规格）+ Technic 梁/销拼装，迭代零等待
- 机身：中央矩形框架放电池 + 主控，四角各出一条 2 关节腿
- 建模尺寸：**大腿 L1 = 小腿 L2 = 55mm**（实物量出来差多少就改 `GAIT_THIGH_MM/GAIT_SHIN_MM`，
  所有运动学、站立高度、蹲下高度会自动跟着变）
- 脚端用 Technic 轮胎/光滑销做脚垫增大摩擦；电池（最重件）置于底层平面降重心

### 2.4 装配基准（最关键的一步，做错了全部重来）

> **把四条腿摆成"站立姿态"，再把舵机臂装到 90°。**

站立姿态 = 膝屈 **-38°** → 髋角自动反解 **19.0°** → 髋轴离地 **104.0mm**。

这样 `舵机 90° = 站姿` 的约定成立，后面所有高度和角度才都算得对：

| 姿态 | 膝角 | 髋角 | 髋轴离地 | 髋舵机 | 膝舵机 |
|---|---|---|---|---|---|
| 站立 | -38° | 19.0° | 104.0mm | 90.0° | 90.0° |
| 蹲下 | -60° | 30.0° | 95.3mm | 101.0° | 68.0° |
| 趴下 | -95° | 47.5° | 74.3mm | 118.5° | 33.0° |

装不精确没关系：`cal` 点动 → `trim` 微调 → `save` 存 NVS。
某条腿方向装反（关节角增大却反向转）用 `dir <关节> -1` 翻转，**不要拆装**。

## 3. 运动学（2-DOF 两连杆，竖直平面）

### 3.1 坐标系与约定

```
        髋点 H (0, 0)  ← 机身，离地 H_h = 104mm
             │
     θ1 ─────┤ 大腿 L1
             │
             ● 膝点 K
       θ2 ────╲ 小腿 L2
               ╲
                ● 脚 F (y, -zd)
```

- **y**：脚相对髋点的前后位置，**+ 前**
- **zd**：脚相对髋点的**竖直向下深度**，落地时 `zd = 髋轴离地高度`
- **θ1（髋角）**：0° = 大腿竖直向下，正值向前摆。软限位 **-45° ~ +75°**
- **θ2（膝角）**：0° = 腿完全伸直，负值向后折。软限位 **-100° ~ +8°**

### 3.2 正运动学（FK）

```c
y  = L1·sin(θ1) + L2·sin(θ1 + θ2)
zd = L1·cos(θ1) + L2·cos(θ1 + θ2)
```

### 3.3 逆运动学（IK）—— 步态引擎的核心

```c
float d      = sqrtf(y*y + zd*zd);            /* 髋点到脚的距离 */
float cos_k  = (d*d - l1*l1 - l2*l2) / (2*l1*l2);
float knee   = -acosf(cos_k);                 /* 负 = 向后折 */
float hip    = atan2f(y, zd)
             - atan2f(l2*sinf(knee), l1 + l2*cosf(knee));
```

工程细节（都已实现，不是纸上公式）：

- `d_max = (L1+L2)·0.998`：**不让自己解到完全伸直**，直腿在实物上等于顶死
- `d_min = |L1-L2| + 0.5`：防止两连杆重叠
- 越界时返回 `clamped = ±1`，`servo_clamp_count()` 累计次数，`status` 会告警
  —— 这是"步幅开太大、腿根本够不到目标"的唯一可靠信号

PC 端实测：858 组 (y, lift) 往返 IK→FK **最大误差 0.000015mm**。

### 3.4 站立髋角为什么不能"随便给"

如果髋角独立指定（比如"髋 12° + 膝 -38°"），解出来的脚会落在髋点**后方 12.7mm**，
四条腿整体偏移，重心就跑出支撑面 —— 站着都在往前栽。

正确做法：**屈膝角是唯一输入，髋角必须由"脚落在髋点正下方"反解**：

```
y = L1·sinθ1 + L2·sin(θ1+θ2) = 0
→ tanθ1 = -L2·sinθ2 / (L1 + L2·cosθ2)
→ θ1 = atan2(-L2·sinθ2, L1 + L2·cosθ2)
```

两条腿等长时有个漂亮性质：**髋角恒等于 -膝角/2**（-38° → 19°，-60° → 30°，-95° → 47.5°）。
所以蹲下/趴下的中间插值状态本身都是合法站姿，脚既不离地也不穿模。

### 3.5 机身高度与姿态

```
H_h = L1·cos(θ1) + L2·cos(θ1 + θ2)
```

蹲下、趴下**不是插值关节角**，而是改屈膝角 → 重算机身高度 → IK 让脚永远踩地。
握手/挥手则是在站姿基础上，给某条腿的脚加 `(foot_y, foot_lift)` 偏移再解 IK：

| 姿态 | 膝角 | 额外偏移 |
|---|---|---|
| 握手 shake | -38° | FR 脚抬起 34mm、前伸 22mm |
| 挥手 wave | -38° | FR 脚抬起 30±10mm（正弦）、前伸 20mm |

## 4. 步态设计

### 4.1 与 OpenCat 的根本区别

| | OpenCat / Bittle | Spider8 |
|---|---|---|
| 相位用法 | 相位 → 余弦波 → **直接**是肩舵机角 | 相位 → 脚的**目标位置** → IK → 髋/膝两角 |
| 膝关节 | **全程锁死**，靠"斜腿 + 摩擦"蹭 | **参与运动**，负责抬脚与贴地补偿 |
| 抬腿 | 不做，脚贴地蹭过去 | 必做，否则拖地 |
| 驱动 | Arduino `delay()` 阻塞 | FreeRTOS `vTaskDelayUntil` 定拍 |

**为什么必须多做 IK 这一步**：2-DOF 腿一摆髋，脚就画圆弧上下起伏。膝角锁死时，
支撑相脚会在 **0 ~ 6.7mm** 之间漂，机身跟着颠。IK 让膝盖反向补偿，把脚按在地面上，
机身起伏才能做到 **0.000mm**。这是 bittle 能糊、我们不能糊的地方。

### 4.2 相位表（4 个数字换一种步态）

`uint8_t` 相位，**256 = 一个完整周期**。四条腿各偏移多少，只由这张表决定：

```c
static const uint8_t PATTERN_PHASE[4][4] = {
    /* WALK  */ {  64, 192,   0, 128 },   /* 传波 RL→FL→RR→FR */
    /* TROT  */ {   0, 128, 128,   0 },   /* 对角同相 */
    /* PACE  */ {   0, 128,   0, 128 },   /* 同侧同相 */
    /* BOUND */ {   0,   0, 128, 128 },   /* 前后成对 */
};
```

`uint8_t` 加法天然回绕，正好替代 OpenCat 那套取模运算 —— 它设计里最省的一块，照抄。

### 4.3 摆动窗与占空比

每个控制拍：

```
ph = (tick × 256 / ticks_per_cycle + 该腿相位) & 0xFF
swinging = (ph < 256 × duty_pct / 100)
```

- 支撑相：脚从 `+stride` 匀速退到 `-stride`（相对机身向后拖，产生前进推力）
- 摆动相：脚从 `-stride` 抬着走到 `+stride`，抬脚高度按 `sin²` 包络（起落无速度突变）

**占空比的硬约束**：波步的相位间隔是 25%，所以 `duty_pct` **必须 ≤ 25**。
超过就会出现两条腿同时离地 —— 那不是波步，是跌跌撞撞的小跑。

| 步态 | duty | 最少支撑腿 | 性质 |
|---|---|---|---|
| walk | 25% | **3 条** | 静态稳定 |
| trot / pace / bound | 25% | 2 条 | 动态平衡，靠惯性 |

> 相位比较用整数 + epsilon 处理边界（`ph + eps < bound`），避免浮点恰好落在边界时
> 把支撑腿误判成摆动腿 —— 这个 bug 在 JS 仿真里真实出现过，固件用整数相位天然规避。

### 4.4 差速转向（2-DOF 唯一的转向手段）

```c
leftRatio  = turn > 0 ? 1 : (10 + turn) / 10.0    /* turn>0 右转：左侧步幅不变、右侧缩小 */
rightRatio = turn > 0 ? (10 - turn) / 10.0 : 1
```

不新增"转向步态"，只是左右两侧步幅不等。`turn=±100` 时内侧步幅降到 0 → 原地转向。
实测 `turn=100`：左侧摆幅 57.6°，右侧 23.7°。

### 4.5 参数表与默认值

| 参数 | 命令 | 默认 | 范围 | 说明 |
|---|---|---|---|---|
| 周期 | `period` | 1200ms | 800~3000 | 低于 800 舵机跟不上 |
| 占空比 | `duty` | 25% | 10~45 | 波步必须 ≤25 |
| 步幅半幅 | `stride` | 22mm | 8~30 | 脚在髋点前后 ±stride |
| 抬脚 | `lift` | 14mm | 6~26 | 超过 20mm 角速度吃紧 |
| 速度 | `speed` | 100% | 0~100 | 线性缩放步幅 |
| 转向 | `turn` | 0 | -100~100 | >0 右转 |

**默认参数实测**：前进 44.0mm/周期 = 36.7mm/s，走 2 米约 55 秒，峰值角速度 **477°/s**（余量 21%）。

### 4.6 舵机速度是物理天花板

MG90S 0.1s/60° → **600°/s**。超了这个值，指令角会跑到机械角前面，脚就绊。

| 参数变化 | 峰值角速度 | 结论 |
|---|---|---|
| 默认（1200ms / 抬脚 14mm） | 477°/s | ✓ 余量 21% |
| 抬脚 16mm | 516°/s | ✓ 余量 14%（偏紧） |
| 周期 900ms | ~560°/s | ⚠ 余量太小 |
| 周期 800ms | ~680°/s | ✗ 超限，必拖地 |

`gait_estimate()` 每次 `status` 跑一遍完整周期算峰值，超限直接标红 ——
不让参数调过头了再让人猜"为什么脚在拖地"。

## 5. 软件架构

### 5.1 任务划分（全部静态创建）

| 任务 | 优先级 | 栈 | 周期 | 职责 |
|---|---|---|---|---|
| `servo_out_task` | **7** | 3072 | 20ms | 唯一写 LEDC；软限位/硬限位/单拍限速 |
| `motion_task` | 5 | 4096 | 20ms | 步态/位姿/标定三选一，斜率限制，投递关节角 |
| `console_task` | 3 | 4096 | 事件 | 串口 REPL（`esp_console`） |

- 两个周期任务都用 **`vTaskDelayUntil`**（不是 `vTaskDelay`）。开环舵机的节奏一散就绊，
  `vTaskDelay` 会被其他任务挤歪，绝对相位越漂越远。
- `servo_out` 优先级高于 `motion`：PWM 刷新不能被打断太久，否则 50Hz 时序抖动。

### 5.2 队列：长度 1 + 覆盖写

```c
xQueueOverwrite(q, &target);   /* 生产者：永远写最新的 */
xQueuePeek(q, &target, ...);   /* 消费者：取最新，不出队 */
```

为什么不排队：舵机是实时设备，**过期的目标角没有价值**。排队会导致"消费慢 → 积压 →
延迟越来越大 → 动作全部走形"。长度 1 + 覆盖写保证永远执行最新指令；
motion 万一卡死，servo 保持最后姿态（不是失控，也不是空转）。

### 5.3 三种模式，一个出口

| 模式 | 来源 | 输出 |
|---|---|---|
| `MODE_POSE` | `pose` 命令 / `demo` | 静态位姿求解 |
| `MODE_WALK` | `walk` / `trot` / `speed` / `turn` | 步态引擎 |
| `MODE_MANUAL` | `cal` 命令 | 直接指定单个关节角 |

统一出口是 **8 个关节角**，全部经过斜率限制（`MOTION_SLEW_DPS = 550°/s`）后投递。
这样任何模式切换、参数突变，落到舵机上都是"20ms 最多走 11°"，永远不会收到跳变指令。

> 标定模式例外：不走 motion 层斜率限制（否则点动一个关节要等好几拍），
> 但仍受 servo 层 12°/拍 保命闸保护。

### 5.4 三道保护（从外到内）

| 层 | 机制 | 参数 | 防的是什么 |
|---|---|---|---|
| 1 | 关节角软限位 | 髋 -45~75°，膝 -100~8° | 机构顶死、拉杆崩 |
| 2 | 电子硬限位 | 舵机角夹 0~180° | 标定手滑输出 3000µs 烧舵机 |
| 3 | 单拍限速 | 20ms 最多 12°（=600°/s） | 指令突跳把齿轮打崩 |

`servo_clamp_count()` 记录软限位触发次数，`status` 超过 0 就报警 —— 这是"步幅/抬脚超了
机构行程"的直接证据。

### 5.5 电气验证通道（raw 模式）

舵机没到货时要能验证 8 路 PWM，所以 `servo` 里留了一条**旁路**：

```c
servo_raw_enter();       /* 冻结 servo_apply，步态/姿态不再改写占空比 */
servo_raw_us(j, 1500);   /* 直接输出脉宽 */
servo_raw_exit();        /* 解冻；随后 motion_stand() 平滑回位 */
```

退出时会把 raw 输出的脉宽反算成等效舵机角存进 `s_servo[]`，这样单拍限速是从
"当前实际位置"接续的，姿态回位不会突跳。详见 `08-LED与PWM验证.md`。

## 6. 串口命令协议（`spider8>` 提示符）

**物理通道：ESP32-S3 原生 USB Serial/JTAG（板上的"USB"口，VID 303A PID 0009），
不是 UART0。** 波特率参数对 USB CDC 无实际意义，`monitor`/串口工具统一写 115200 即可。

为什么不走 UART0：UART0 只引到板上标 `UART` 的 Micro-USB（CH340），而这台机器上
CH340 驱动不可用；"USB"口是免驱的原生 USB，是唯一可靠通道。因此 `sdkconfig` 里
`CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG=y`，REPL 由 `esp_console_new_repl_usb_serial_jtag()` 创建。

| 命令 | 参数 | 说明 |
|---|---|---|
| `help` | | 列出所有命令 |
| `status` | | 8 关节角/舵机角/dir/trim、步态参数、峰值角速度余量、堆越界次数、堆栈余量 |
| `demo` | | 演示：蹲→站→握手→挥手（约 9 秒） |
| `pose` | `stand\|crouch\|lie\|shake\|wave` | 切换姿态（0.45s 平滑过渡） |
| `walk` | `[0-100]` | 波步行走 |
| `trot` | `[0-100]` | 小跑 |
| `stop` | | 停止并站定 |
| `speed` | `<0-100>` | 速度百分比 |
| `turn` | `<-100..100>` | 差速转向，>0 右转 |
| `period` | `<800-3000>` | 步态周期 ms |
| `stride` | `<8-30>` | 步幅半幅 mm |
| `lift` | `<6-26>` | 抬脚高度 mm |
| `duty` | `<10-45>` | 摆动相占空比 % |
| `cal` | `<0-7> <关节角>` / `off` | 单关节点动（旁路软限位） |
| `trim` | `<0-7> <-50..50>` | 舵机微调角（上限见 `SERVO_TRIM_LIMIT_DEG`） |
| `dir` | `<0-7> <1\|-1>` | 翻转舵机方向 |
| `save` | | trim/dir 写 NVS |
| `pwm` | `<0-7\|all> <500-3000>` / `off` | 电气验证：固定脉宽输出（上限 3000 供 360° 大行程舵机测端点） |
| `pwmscan` | `<0-7\|all>` | 电气验证：呼吸扫描 |

## 7. 后续扩展设计（M3+，尚未实现）

### 7.1 BLE 协议（NUS + 二进制帧）

服务 `6E400001-B5A3-F393-E0A9-E50E24DCCA9E`（微信小程序 BLE 直接兼容）。

| 类型 | 帧格式 |
|---|---|
| 摇杆 | `0xA1 \| x:int8 \| y:int8 \| seq`（50ms 心跳，500ms 断连→停车） |
| 模式 | `0xA2 \| mode(0=手动/1=自动/2=停止)` |
| 动作 | `0xA3 \| action_id` |
| 舵机微调 | `0xA4 \| ch \| trim:int8` |
| 姿态预设 | `0xA5 \| pose_id` |
| 遥测（上行1Hz） | `0xB1 \| battery:mV/10 \| mode \| dist_cm \| seq` |

### 7.2 避障状态机（无 IMU 降级方案）

```
CRUISE ──dist<25cm──► STOP ──► BACK(退1s) ──► TURN(差速转 90°±30°)
   ▲                                              │
   └──────────────── 恢复直行 ◄────────────────────┘
连续 3 次未脱离 → 原地换向 180°
```

### 7.3 动作库

关键帧 JSON 存 LittleFS，帧间线性插值 50Hz。内置：挥手 / 趴下 / 扭屁股 / 小碎步 / 点头。

## 9. 测试策略（三层，越靠前越便宜）

| 层 | 工具 | 覆盖 | 成本 |
|---|---|---|---|
| 算法 | `tools/fw_test/test_gait.c`（gcc 直编） | IK 精度、支撑腿数、舵机行程、角速度、姿态高度 | 秒级，不碰硬件 |
| 视觉 | `tools/gait_sim/index.html` + `verify.js` | 关节是否打架、脚是否拖地、参数权衡 | 秒级，靠眼睛 |
| 页面回归 | `tools/gait_sim/harness.js` | canvas 尺寸、坐标越界、DOM 节流 | 秒级，无头 |
| 硬件 | 串口 CLI + LED/万用表 | PWM 波形、实际角度、标定 | 分钟级，需接线 |

**原则**：纯算法能离线验证的，绝不拖到板子上才发现。`gait.c` 不 include 任何 ESP-IDF 头文件，
正是为了能在 PC 上直接编译。

## 10. 里程碑与风险

| 里程碑 | 内容 | 验收标准 |
|---|---|---|
| M0-1 | 固件骨架 | ✅ 心跳日志稳定，烧写链路通 |
| M0-2 | 舵机驱动 + 步态引擎 | 编译通过 + PC 单测全绿 + LED 验证 8 路 PWM |
| M1 | 标定 + 单腿 | 8 个中位一致；单腿"抬-前-落-拖"平滑 |
| M2 | 站立与姿态 | 站立 ≥5min 不抖，蹲/趴/站可切换 |
| M3 | 遥控行走 | BLE 接入；直行 2m 偏差 <15cm，可转弯 |
| M4 | 自动避障 | 25cm 障碍绕行 ≥80% |
| M5 | 动作库 + 保护 | ≥6 动作流畅；低压自动趴下 |
| M6 | 外观 + 联调 | LED 眼睛/音效/外壳，全功能演示 |

### 风险与对策

| 风险 | 对策（已内置于设计） |
|---|---|
| MG90S 无反馈，堵转烧毁 | 软限位 + 硬限位 + 单拍 12° 限速 + 舵机独立电源轨 |
| 无 IMU，跌倒无法自恢复 | 一键趴下 + 避障保守参数（低速、提前转向） |
| 2-DOF 不能横移 | 差速转向；避障用"退一步再转"，不指望原地横挪 |
| 舵机速度上限 | `status` 实时显示余量，超限标红；周期下限 800ms 写进约束 |
| 乐高关节旷量 | 摆动相留余量，落地拍加重插值，金属舵机臂 |
| 8 舵机共轨干扰 | 独立 5V/5A 轨 + 2200µF + AMS1117 隔离主控 |
