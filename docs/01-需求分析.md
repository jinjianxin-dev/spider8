# 四足机器狗「Spider8」需求分析

> 项目代号：Spider8 ｜ 文档版本：**v2.0** ｜ 日期：2026-11-04
> 主控平台：ESP32-S3-N16R8（双核 Xtensa LX7 @240MHz，16MB Flash，8MB PSRAM，WiFi 2.4G + BLE 5.0）
>
> **v2.0 变更说明（重要）**：本文档 v1.x 写的是「四足蜘蛛」——髋轴竖直、腿在水平面内左右划。
> 实际按此方案做出来的是螃蟹的走法，与真正的机器狗完全不同。v2.0 起项目定位改为
> **四足机器狗**：髋轴水平、腿在竖直平面内前后摆、膝盖上下折叠。关节几何、步态、
> 甚至"能不能转弯"的结论都随之改变，详见 §2。

---

## 1. 项目概述

制作一只**四足仿生机器狗**，每条腿 2 个关节（共 8 个舵机），支持：

- 串口命令行直接控制（现阶段唯一入口，没有 App 也能完整验收）
- 手机蓝牙遥控（下一阶段，微信小程序虚拟摇杆）
- 四种步态：波步（稳）/ 小跑（快）/ 溜蹄 / 跳跃
- 静态姿态：站立、蹲下、趴下、握手、挥手
- 超声波自动避障（后续）
- 按软件工程流程推进：需求分析 → 设计方案 → 原型迭代 → 验收记录

## 2. 形态定义（为什么必须是"狗"）

这是本项目最容易被搞错、也最贵的一处，单独列出来。

### 2.1 两种关节几何的区别

| | 蜘蛛形态（v1.x 误用） | 狗形态（v2.0 正确） |
|---|---|---|
| 髋关节转轴 | **竖直**轴 | **水平**轴（垂直于身体前后方向） |
| 腿的运动平面 | 水平面 —— 像螃蟹左右划 | 竖直面 —— 像划船前后摆 |
| 膝关节 | 只负责抬放 | 上下折叠，负责抬脚 + 调节身高 |
| 正运动学 | `x = r·cos θ`（绕竖直轴转 XY） | `y = L·sin θ`，`z = L·cos θ`（竖直面） |
| 视觉特征 | 从**上往下**看才看得清 | 从**侧面**看才看得清 |

两者算出来的足端轨迹完全不是一条曲线。用蜘蛛的公式去驱动狗形结构，腿会往侧面甩，
一步都走不了直线。

### 2.2 每条腿的几何（两连杆）

```
        机身（髋轴离地约 104mm）
   ────────●═══════════════════●────────
           │ 髋关节 H（水平轴，θ1 前后摆）
           │ 大腿 L1 = 55mm
           │
           ● 膝关节 K（θ2，负值向后折）
            ╲
             ╲ 小腿 L2 = 55mm
              ╲
               ● 脚 F（着地点）
```

- **θ1（髋角）**：0° = 大腿竖直向下，正值 = 向前摆
- **θ2（膝角）**：0° = 腿完全伸直，负值 = 小腿向后折（屈膝）
- 关节角 → 舵机角：装配时把腿摆成站姿、舵机臂装到 **90°**，之后线性映射（见 02 文档 §3）

### 2.3 2 自由度带来的硬限制

这几条不是"暂时没做"，而是**几何上做不到**，写进需求以避免后期返工：

1. **脚不能横向跨步**。腿只在一个竖直平面内前后动，脚无法挪到身体侧面去。
   → 不能侧移、不能横着走；**转向只能靠左右两侧步幅差动**（差速），不能像 3-DOF 那样侧摆转向。
   侧向打滑也无法主动纠正（没有外展关节，也没有 IMU）。
2. **单腿工作空间是一个"扇形环"**。脚能到达的区域受 `L1+L2 = 110mm`（拉直）与
   `|L1-L2| = 0`（顶死）限制。**步幅 + 抬脚高度 + 机身高度三者共享这一份预算**，
   谁的参数开太大都会让脚"够不着目标"。固件里 `clampN` 就是超预算的计数，`status` 会告警。
3. **"握手"做不出真正的横向递爪**。实现是"抬起 + 前伸"，视觉上像伸手，方向其实朝前。
   想做真侧向得加第三个关节（Bittle 就是 3-DOF）。

> 注：**不要**把"脚只能走圆弧"当成 2-DOF 的限制 —— 那是"膝角锁死只摆髋"时的现象。
> 我们做了逆运动学，膝盖会反向补偿，支撑相脚可以走**纯水平直线**（机身起伏实测 0.000mm）。
> 这也是"必须做 IK"的直接理由。

## 3. 硬件需求

| 序号 | 部件 | 方案 | 说明 |
| --- | --- | --- | --- |
| H1 | 主控 | ESP32-S3-N16R8 | WiFi+BLE 双模，LEDC 8 通道恰好驱动 8 路舵机 |
| H2 | 舵机 | **8 × MG90S**（金属齿轮） | 每腿：髋（水平轴前后摆）+ 膝（上下折叠）。**速度 0.1s/60° = 600°/s 是硬上限**，见 §5 |
| H3 | 电源 | 2S 锂电池（7.4V）+ DC-DC 降压 | 舵机独立 5V 轨，与主控 3.3V 隔离，防堵转拉低电压导致复位 |
| H4 | 避障传感器 | 超声波 HC-SR04 | 装于头部前方，探测 3~200cm |
| H5 | 姿态传感器 | ~~MPU6050~~ **暂不做**（D3 决策） | 无 IMU → 无跌倒自恢复，改为「一键趴下」按钮 |
| H6 | 电量监测 | ADC 分压采样 | 低电压告警 + 欠压保护（保护锂电池） |
| H7 | 效果件 | WS2812 LED 眼睛 ×2 + 无源蜂鸣器 | 可爱化：眨眼、变颜色、叫声音效（可选） |
| H8 | 结构 | **乐高 Technic 拼装先行** | 迭代零等待，后续可换 3D 打印外壳 |

## 4. 功能需求

### FR-1 行走（P0 必做）

- **四种步态**，用 4 个数字的相位表切换，代码不动：

| 步态 | 相位表 `{FL, FR, RL, RR}`（256 = 一周期） | 最少支撑腿 | 性质 |
|---|---|---|---|
| 波步 walk | `{64, 192, 0, 128}` → 传波顺序 **RL→FL→RR→FR**（后腿先动） | **3 条** | 静态稳定，抬一条腿重心还在三角形内 |
| 小跑 trot | `{0, 128, 128, 0}` 对角同相 | 2 条 | 快，需要惯性，适合平整地面 |
| 溜蹄 pace | `{0, 128, 0, 128}` 同侧同相 | 2 条 | 会左右摇，只做演示 |
| 跳跃 bound | `{0, 0, 128, 128}` 前后成对 | 2 条 | 最激进，损坏风险高 |

> 波步的离地顺序是 RL→FL→RR→FR，也就是四足动物最常见的**侧序步态（lateral sequence）**：
> 后腿先蹬、再从后往前传波。只有在 `duty ≤ 25%` 时才能保证"任意时刻只有一条腿离地"，
> 实测最少支撑 3 条 —— 这条约束比顺序本身更要紧，占空比开到 30% 就退化成小跑了。
> 换顺序只动这 4 个数字，代码一行不用改。

- **调速**：速度 0~100% 线性缩放步幅；周期 800~3000ms 可调
- **转向**：差速转向，左右两侧步幅不等，不需要单独的转向步态
- **参数在线可调**：周期、占空比、步幅、抬脚高度、速度、转向，全部串口即时生效

### FR-2 静态姿态（P0 必做）

| 姿态 | 机身髋轴高度 | 说明 |
|---|---|---|
| 站立 stand | **104.0mm** | 基准姿态，装配与标定的参照 |
| 蹲下 crouch | 95.3mm | 屈膝 -60° |
| 趴下 lie | 74.3mm | 屈膝 -95°，快贴地 |
| 握手 shake | 104.0mm | 右前腿抬起 34mm + 前伸 22mm |
| 挥手 wave | 104.0mm | 右前腿抬起并上下摆 |

- 姿态切换必须**平滑过渡**（0.45 秒插值 + 斜率限制），不能瞬变
- 蹲下/趴下**不是插值关节角**，而是改屈膝角 → 重算机身高度 → 逆运动学让脚永远踩地

### FR-3 串口命令行（P0 必做，现阶段唯一入口）

- 115200 波特率，`spider8>` 提示符
- 覆盖：姿态切换、行走、参数调整、单关节标定、状态查询、动作演示
- `status` 必须能自我诊断：舵机角、峰值角速度余量、软限位触发次数、堆栈余量

### FR-4 单关节标定（P0 必做）

- 首次使用必做：把 8 个舵机的中位对齐到装配基准
- `cal` 点动 → `trim` 微调 → `save` 写 NVS，掉电不丢
- 某条腿方向装反时用 `dir -1` 翻转，不要拆装

### FR-5 手机遥控（P1）

- BLE（微信小程序），虚拟摇杆控制前进/后退/左右转
- 动作按钮、舵机微调、步态切换、电量显示
- 断连 500ms 自动停车

### FR-6 自动避障（P1）

- 直线行走，前方 20~30cm 检测到障碍 → 停止 → 后退 → 差速转向绕行
- 无 IMU，卡死检测只能靠"指令下发但位置不变"的间接判断（当前版本不做）

### FR-7 电气验证（P0，可以先于舵机到货做）

- **没有舵机也能验证 8 路 PWM**：LED + 电阻接信号脚，或万用表量平均电压
- 提供 `pwm <通道> <脉宽>` 固定输出与 `pwmscan` 呼吸扫描两条命令
- 每一步的期望现象必须写死成验收表（见 `08-LED与PWM验证.md`）

### FR-8 可扩展（P2）

- 动作库（关键帧 JSON）、红外跟随、声音音效、摄像头接口

## 5. 非功能需求

| 类别 | 指标 | 依据 |
|---|---|---|
| 实时性 | PWM 50Hz（20ms），步态控制拍 20ms，指令延迟 < 100ms | MG90S 标准信号 |
| **角速度** | **峰值 ≤ 600°/s，设计留 25% 余量** | MG90S 0.1s/60°，超了指令角会跑在机械角前面，脚就绊 |
| **周期下限** | **不得低于 800ms** | 低于此值摆动相太短，舵机跟不上 |
| 续航 | ≥ 30 分钟连续行走（2S 18650 ×2） | |
| 载荷 | 每个关节扭矩余量 ≥ 2 倍静态需求 | MG90S 2.2kg·cm @5V |
| 稳定性 | 舵机堵转不导致主控复位；看门狗兜底 | 独立舵机电源轨 + 大电容 |
| 内存 | FreeRTOS **静态分配**任务栈，运行期零动态分配 | 项目规范 |
| 成本 | 整机 ¥300~600 | |

> **默认参数实测**：周期 1200ms、步幅 ±22mm、抬脚 14mm → 峰值角速度 **477°/s**（余量 21%）、
> 前进 44mm/周期 = 36.7mm/s，走 2 米约 55 秒。想快就压周期或加步幅，`status` 会实时报余量。

## 6. 约束与风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 8 舵机同时动作电流峰值 5~8A | 电池/降压模块过载、电压跌落复位 | 舵机独立 5V/5A 轨 + 2200µF 电容 + 软启动 |
| PWM 舵机无位置反馈 | 堵转烧毁 | 软限位 + 电子硬限位 + 单拍 12° 限速三道闸 |
| **2-DOF 不能横移** | 转向与避障灵活度受限 | 差速转向；避障采用"退一步再转"策略，不指望原地横挪 |
| **步幅/抬脚超出腿长** | 脚够不到目标位置，机身被"拽"下去，走起来一顿一顿 | IK 越界时返回 `clamped`，固件累计 `clampN`，`status` 超过 0 就告警 |
| **占空比开太大** | 两条腿同时离地，波步退化成小跑 | `duty` 上限 45%，波步手册写死 ≤25%（PC 单测校验最少支撑 3 条） |
| 乐高结构关节旷量 | 步幅损失、落地抖 | 摆动相留余量，舵机臂用金属件，脚底加摩擦垫 |
| 舵机速度上限 | 想快只能加大步幅，不能无限压周期 | `status` 显示峰值角速度余量，超限标红 |
