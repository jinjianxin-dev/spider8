## 排错记录（重要经验）
1. **export.ps1 激活失败**：IDF 5.5 的 export.ps1 调 PATH 里的 `python`(系统3.14.6) 跑 activate.py → 失败。修复：idf.ps1 激活前把 IDF venv（`E:\esp\.espressif\python_env\idf5.5_py3.13_env`）的 Scripts 目录提到 PATH 最前。
2. **PS 5.1 把子进程 stderr 当终止错误**：`$ErrorActionPreference="Stop"` 时 python 的任何 stderr 输出都会抛 NativeCommandError → 包装脚本改用 Continue。
3. **【机器级】全局 git 配置有失效代理**：`url.https://ghproxy.com/https://github.com/.insteadOf = https://github.com/`（ghproxy.com 已停服）→ 所有 github 克隆被劫持到坏代理，导致 IDF 子模块缺 commit/损坏。绕过方法：`GIT_CONFIG_GLOBAL=/dev/null`。已告知用户可自行删除该规则；本项目脚本用绕过法，不动用户全局配置。
4. **Gitee 镜像的 esp-idf 缺部分子模块仓库**（404 要求输密码），且镜像改写过的 .gitmodules 用相对 URL 会解析回 gitee → 解法：下载 GitHub 官方 v5.5.5 的 .gitmodules，相对地址改写为 `https://github.com/`，`git submodule sync` 后用 `--jobs 8` 并行更新，配合"检测 Unable to find current revision → deinit → 重拉"循环修复，3 轮全部修复（23/23）。
5. 全量编译 1079 单元约 25 分钟（此机器），后续增量会快很多；ccache 已装但首次构建未显著命中。
