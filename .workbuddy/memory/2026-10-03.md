## 【重要教训】VS Code 任务"永远在执行中"——默认终端 profile 的坑（已修）
- 用户报"烧写任务还在执行中"，排查发现 PID 命令行是：
  `PS 解释器 -NoExit -ExecutionPolicy Bypass -Command . 'E:\esp\esp-idf\export.ps1' -Command <任务命令行>`
- **机制**：VS Code 跑 `type: shell` 任务时，若任务没显式指定 shell，就用 `terminal.integrated.defaultProfile`，
  并把**任务命令行追加到 profile 的 args 之后**。我之前把带 `-NoExit` 且含 `-Command` 的「ESP-IDF Shell」设为默认终端
  → 追加的任务命令被 profile 的 `-Command` 吞成 `export.ps1` 的参数 → **任务根本没跑**，只是空转。
- **两个现象同一根因**：① 报 `C:\Users\aaron\.espressif\python_env\idf5.5_py3.14_env not found`（来自 profile 里那句裸 `. export.ps1`：无 IDF_TOOLS_PATH + 解释器 3.14，**与 idf.ps1 无关**）；② `-NoExit` 使 shell 永不退出 → 任务永远显示执行中。
- **修复（三层）**：
  1. `tasks.json` 每个任务加 `options.shell`（`{executable: powershell.exe, args:[-NoProfile,-ExecutionPolicy,Bypass,-File]}`），`command` 直接指向 `tools/idf.ps1`，不再套一层 —— **与默认 profile 彻底解耦**
  2. 新增 `tools/idf_shell.ps1`：终端专用启动脚本（先钉死 IDF_TOOLS_PATH/IDF_PYTHON_ENV_PATH 再激活），用 `return` 不用 `exit`（否则会关掉终端）；settings.json 的 ESP-IDF Shell profile 改调它
  3. 所有任务加 `"presentation": {"showReuseMessage": false}`
- **验证**：任务命令行方式 `build` 22.8s 自行退出(码0)；profile 方式输出 `[OK] ESP-IDF v5.5.5-dirty`(码0)
- **通用规则（写进 MEMORY.md）**：带 `-NoExit` 的终端 profile **绝不能**当任务 shell；任务必须显式 `options.shell`。
- 清理卡住任务的办法：终端标签的 🗑 图标 / `Ctrl+Shift+P → Tasks: Terminate Task` / 关面板。
